## Authoring Contract (file shape, ids, hooks)

These rules exist because three consumers read the file mechanically: the GUI-02 pytest (html.parser), `scripts/mockup-id-check.py` (regex), and the Playwright tests.

### File shape

1. Path `mockups/operator-console.html` (a directory the BAK mockup scan skips). One file. No `<link>`, no `<script src>`, no `<img src>`, no `@import`, no `url(http...)`, no web fonts. GUI-01 asserts zero requests.
2. Order inside `<body>`: one wrapper `<div data-mock-id="shell.root.app" data-mock-variant="console-a">` that contains the header, nav, six screen roots, the four dialogs and the `<svg hidden>` sprite. After the wrapper closes come all `<script>` elements. The `<style>` element sits in `<head>`. No `<script>` or `<style>` element is inside the wrapper.
3. Variant name `console-a` `(default)`. The owner freeze records `{variant: "console-a", path: "mockups/operator-console.html", sha256}` in `ledger/REQUIREMENTS.json` `mockup_freeze`.
4. Fixtures are inline: one `<script type="application/json" id="mock-fixtures">` block, placed outside the wrapper. Shapes follow API-INVENTORY section 3 exactly (field names, nullability, ordering).

### Constraints that come from `scripts/mockup-id-check.py`

| Rule | Reason |
|------|--------|
| Every id is written as `data-mock-id="..."` with double quotes, lower case attribute name. | `ID_RE` matches only that form. |
| No attribute value anywhere in the wrapper contains a raw `<` or `>`. Write `&lt;` and `&gt;`. | `TAG_RE` is `[^<>]*?`; a stray angle bracket ends the tag early and breaks variant span matching. |
| All `<div>` open and close tags inside the wrapper are balanced; no self-closed `<div/>`. | The span matcher counts nested tags of the variant's tag name. |
| No `data-mock-id="..."` text inside `<script>` strings or comments that sit inside the wrapper. JS addresses elements with `[data-mock-id="x"]` selectors only (the regex lookbehind skips `[data-mock-id=`). | Prevents phantom ids. |
| Ids exist as literals in the file. JS never creates, renames or removes ids. | The checked-in list and the port check read the source, not the DOM. |
| Repeating rows that hold a control are pre-rendered slots, not generated markup. JS fills text and toggles `hidden`. Rows that hold no control may be built with `document.createElement` plus `textContent`. | Keeps ids unique and literal; a row with no control has no id to keep. |
| A view that must be ABSENT from the DOM (the non-debug trace has no node table) is a `<template>` whose single clone is inserted on demand and removed when the toggle is turned off. Its ids still appear once in the source. | GUI-07: "node table is absent". |

### Id grammar (default scheme from GUI-02)

- Screen roots: `screen-query`, `screen-evidence`, `screen-documents`, `screen-corpus`, `screen-ledger`, `screen-graph`. Single segment, tested by GUI-01.
- Everything else: exactly three dot-separated segments `<screen>.<region>.<control>`; each segment is lower case `[a-z0-9]+(-[a-z0-9]+)*`. Regex: `^[a-z0-9]+(-[a-z0-9]+)*\.[a-z0-9]+(-[a-z0-9]+)*\.[a-z0-9]+(-[a-z0-9]+)*$`.
- `<screen>` is `shell`, `query`, `evidence`, `documents`, `corpus`, `ledger` or `graph`.
- Slots: a repeating control takes a numeric suffix on the control segment: `query.evidence.open-3`, `query.col2.open-1`, `ledger.timeline.retire-4`.
- Reserved region `mock`: `<screen>.mock.<control>`, mock-only chrome.
- Reserved region `state`: `<screen>.state.<state>`; `error`: `<screen>.error.<shape>`.
- The checked-in list is `docs/gui/MOCK-IDS.json`: a sorted JSON array of every id in the file, generated once by a script from the final file. The GUI-02 test requires set equality, so renaming or removing an id fails the test.

### Elements that must carry an id (GUI-02 test plus house rules)

Every `button`, `input`, `select`, `textarea`, `a`, `summary`; every element with `role` `tab`, `dialog`, `table`, `status`; every panel, banner, state view, badge group, table and screen root. The GUI-02 test finds regions by the tags `section` and `details`, `role="alert"` and the classes `panel`, `banner`, `state-view` and `badges` defined in `00-base.css` (17-01 Task 2, 17-02 Task 2). `<option>`, `<label>`, `<datalist>` and plain text spans are exempt. Tables carry an explicit `role="table"`. `role="status"` is used only on elements that already need an id (health badge, resolves-to line, pre-flight list, progress lines).

### Disabled and blocked controls

| Situation | Markup | Visible reason |
|-----------|--------|----------------|
| Native disabled (button, input, select, textarea) | `disabled` AND `aria-disabled="true"` | Reason text always visible next to or under the control, never hover-only. |
| Disabled `<a>` (Open trace) | no `href`, `aria-disabled="true"`, `tabindex="-1"` | Reason text visible under the link. |
| Disabled row action with tooltip (Retire) | button `disabled` plus wrapper `<span title="...">` | The status cell of the row also states the reason in text. |
| Query Run (query mode) | NOT disabled. A click with a blocker shows the inline message, focuses it, and does not change state. Messages also appear live after the first edit. | Inline message under the field. |
| Compare Run | `disabled` while any blocker is active | Warning list above the button. |
| Submit buttons (paste, upload), Promote, confirm buttons | `disabled` while a pre-check fails or a call is in flight | Field error or pre-flight list. |

### Test hooks

- `window.__mock.show(screenName)`, `window.__mock.setState(screenName, stateName)`, `window.__mock.inject(screenName, response)`, `window.__mock.loadFixture(screenName, fixtureName)`. `response` is `{status: number, body: object | string}`.
- `inject` runs the single `classifyResponse(status, body)` function used by every real code path (rules in Server Error Shapes).
- Every badge, status line and banner exposes its state in `data-state`. Every hidden element uses the `hidden` attribute with `[hidden]{display:none !important}`.
- Hash routing: nav buttons set `location.hash` to `#query`, `#evidence`, `#documents`, `#corpus`, `#ledger`, `#graph`; load honors the hash. No network is involved.

## Typography

Four sizes, two weights.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (paragraphs, inputs, buttons, table cells) | 14px | 400 | 1.5 |
| Label (field labels, table headers, badges, tab labels, nav labels) | 13px | 600 | 1.5 |
| Data (refs, ids, tokens, hashes, code, key/value values; monospace) | 13px | 400 | 1.5 |
| Heading (panel titles, dialog titles, banner headings) | 16px | 600 | 1.2 |
| Display (screen title, one per screen) | 20px | 600 | 1.2 |

Sizes in use: 13, 14, 16, 20. The 13 to 14 px step is intended: 13 px marks the compact tier (labels, headers, badges and monospace values), set in weight 600 or in the monospace stack so it differs from 14 px Body by more than size, and monospace at 13 px matches the x-height of 14 px sans-serif text on the same line. Weights in use: 400, 600. No italics. Muted text is a color, not a size. Answer text and evidence content render at Body size with `max-width: 72ch` and `white-space: pre-wrap`.

## Server Error Shapes (GUI-06)

All six screens implement the four shapes with the same renderer. `classifyResponse(status, body)` decides, in this order, and never branches on status alone:

| Order | Condition | Shape | Component id suffix |
|-------|-----------|-------|---------------------|
| 1 | `body.refusal_type === "ForeignEngineRefusalError"` (any status) | Server-failure banner | `error.server-failure` |
| 2 | `body.refusal_type` is any other string | Typed refusal banner | `error.refusal` |
| 3 | `status === 422` and `Array.isArray(body.detail)` | Field errors | `error.validation` |
| 4 | `status >= 500`, or any unstructured body, or no response | Generic error view | `error.generic` |
| 5 | 2xx | Result | none |

Body shape of a refusal (from `refusal_body`): flat object `{refusal_type, message, <public attributes>}`. The static catalogue is `docs/gui/refusals.json` (generated; each entry `{refusal_type, module, attribute_keys, http_status}`; the count follows the code and is compared with `SeamRefusalError.__subclasses__()` at test time, D-09). A not-found lookup is 404 for the four lookups (`UnknownTraceReferenceError`, `UnknownJobError`, `UnresolvableEvidenceReferenceError`, `UnknownGenerationVersionError`) and 422 for the rest; the renderer ignores that difference. Every banner and the catalogue are marked by a needs-backend wrapper `GET /refusals` on the `catalogue-link`.
