`databasise/eval/bundle.py` holds the bundle model and its lifecycle. Follow `parity_report.py`'s shape: pure functions over on-disk state, explicit empty-state rendering, no hidden mutation.

`EvalBundle` is a frozen model carrying §EV.1's six members by their own names — `questions`, `gold_answers`, `judge_instance`, `judge_prompt_hash`, `corpus_snapshot_hash`, and the determinism and concurrency settings — plus the three `BundleSplit` partitions and the two `TargetFamily` entries. Name the two families with the identifiers `gold_passage` and `answer_level`, and record each family's `§4` evidence tier alongside it: `T1` and above for gold-passage, `T0` for answer-level, exactly as `§EV.2`'s table states. `mint_bundle` refuses with `MissingTargetFamilyError` when either family is absent — `§EV.2`'s "mandatory bundle content, never a configuration choice" rule enforced at mint time rather than discovered later by a measurement that quietly covered less than it claimed.

The version identifier `bundle@vN` is derived, not chosen: compute a content hash over the RFC 8785 canonicalisation of exactly the five invalidating inputs `§EV.1` names — the question set, the gold answers, the judge instance and judge prompt hash, the corpus snapshot hash, and the determinism/concurrency setting pair — using the existing `databasise/identity/canon.py` `canonicalise` helper and stdlib `hashlib.sha256`, introducing no second hashing scheme. Minting writes a new numbered directory under the bundle root and never touches an existing one; `load_bundle` re-verifies the stored digest and raises `BundleDriftError` naming the version on any mismatch, following `corpus.py`'s and `stores/vector.py`'s shared refuse-rather-than-trust convention.

Splits: assign each question to `dev`, `holdout` or `sealed` deterministically from a hash of its own question id so a remint from the same snapshot reproduces the same assignment, and record the split proportions in the bundle so the assignment is auditable rather than implicit. The three sets are pairwise disjoint and their union is the whole question set; assert both at mint time.

Partition discipline, per `§EV.1`: `dev` is freely readable. `holdout` is readable only after `record_holdout_use` appends a usage entry naming the reader and the reason — the holdout-usage logging MACH-02 requires in force before any decomposition work consults it. `sealed` is not readable at all except through `open_sealed`, which requires a stated opening event, mints a new bundle version because the partition it drew from is no longer sealed once touched, and appends its own usage entry. A `sealed` read that quietly succeeds is the one outcome that destroys the property sealing exists to buy, so both the mint and the log entry are preconditions of the read returning, never follow-ups after it.

Write `databasise/tests/eval/conftest.py` with a bundle-root `tmp_path` fixture and a snapshot fixture loading `tests/fixtures/eval-corpus/`, and `databasise/tests/eval/test_bundle_versioning.py` covering the `<behavior>` block.
