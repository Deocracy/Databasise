<objective>
Close Gap 1(a): give HippoRAG a real write path through the public §18 seam, and correct the phase's
own coverage record so it states what the seam can actually do.

**The choice this plan makes, and why (the gap brief asked for it to be stated).** Two dispositions
were available: a HippoRAG ingest+delete wiring pair, or an explicit named refusal. This plan takes
**both, split by which one the existing node inventory can honestly support**:

- **Ingest — a real wiring.** All seven of HippoRAG's index-side positions already exist and are
  already executed together by `databasise/parity/build_hipporag_index.py` (`chunk-embed`,
  `openie`, `entity-fact-embed`, `fact-edges`, `passage-edges`, `synonymy-edges`,
  `graph-augment-persist`). `databasise/wirings/hipporag/corpus-ingest.json` is therefore a
  **re-composition of node objects already committed in `base.json`** — no new node code, no new
  Part, no new registration. This is exactly the condition the gap brief named for preferring the
  wiring.
- **Delete — the named refusal.** No HippoRAG delete node exists anywhere in the repository:
  removing a document from HippoRAG's index means retracting its chunk/entity/fact vectors and its
  fact/passage/synonymy edges, and nothing in `databasise/parts_core/hipporag/` does any of that. A
  delete wiring would require **new node code**, which the gap brief puts out of scope. So
  `delete_document()` gains `NoWritePathForModalityError`, mirroring `UnknownDocumentError`'s house
  style, and the limitation is stated plainly in COVERAGE.md rather than papered over.

The dispatch itself is deliberately tiny (ponytail): the on-disk layout
`databasise/wirings/<modality>/corpus-<operation>.json` **is** the lookup table. A file that exists
is a supported write path; a file that does not exist is the refusal. No registry, no dict, nothing
to drift out of sync with the filesystem.

Purpose: MODAL-05's real-corpus proof point cannot even be attempted through the product surface
until a caller can populate HippoRAG's index through it; today the only path
(`build_hipporag_index.py`) bypasses `Databasise` entirely.
Output: one new wiring JSON, one new refusal class, a per-modality corpus-wiring resolver, selector
parameters on both write operations across all three transports, one new test module, and a
corrected COVERAGE.md.

**Explicitly NOT in this plan:** the real, spend-incurring cross-modality run (Gap 1(b)) — that is
06-13's own blocking checkpoint. Nothing here makes an LLM or embedding call.
</objective>

<assumption_delta_decision>
**Noun now primary:** *the target modality of a write operation.*

Before this plan the corpus write surface had exactly one implicit modality: `_INGEST_WIRING_PATH`
and `_DELETE_WIRING_PATH` were module constants pointing at LightRAG's two files, and "which index
does this document go into" was not a question the code could ask. This plan introduces the second
modality, so the singular→plural transition is real.

**Decision: `promote`.** The corpus wiring path becomes a *function of the resolved target
modality* (`databasise/wirings/<family>/corpus-<operation>.json`), and LightRAG becomes one variant
of that function rather than the definition of it. The identity that keys the lookup is the same
§18.4 selector the caller already supplies for `query`/`compare` — no second, write-only selector
vocabulary is invented, and no modality name crosses the seam in either direction.

Rationale for `promote` over `add-alongside`: an `add-alongside` shape (keep the LightRAG constants,
add a HippoRAG branch beside them) would leave the *default* write path defined by a specific
modality rather than by a resolution rule, so modality three would add a third branch instead of a
third directory. The promoted shape adds nothing per modality except files on disk.

**Invariant test accepted** (Task 2): every modality this machine resolves query wirings over
(`databasise.wirings.resolve.WIRING_NAMES`) either ships `corpus-ingest.json`/`corpus-delete.json`,
or `ingest()`/`delete_document()` raise `NoWritePathForModalityError` for it — never a silent
fallback to another modality's wiring.
</assumption_delta_decision>
