<objective>
Close both of Falsifier 5's named preconditions — the two things
`databasise/evidence/FALSIFIER-5-EVIDENCE.md` says must hold before a real A/A calibration can run —
without spending anything.

**Precondition 2 first (it is the tracer): a cost-bounded ingest path for the 291-document
eval-corpus.** The blocker recorded in FALSIFIER-5-EVIDENCE.md is not that ingest is expensive, it
is that it is *unbudgetable*: v1's `full-ingest` reports `counted_by="unbudgetable"`, so no bound
can be enforced from inside the run. The bound that *is* available is therefore the one on the
outside — document count — plus an a-priori projection the owner can price. This plan builds
`databasise/eval/corpus_ingest.py`: a dry-run-by-default entry point that prints a real, computed
projection for the first N documents and ingests only when an explicit opt-in flag is passed,
driving the public `Databasise.ingest()` seam (which 06-10 just made per-modality) one document at a
time so a run can be stopped at any document. That turns the checkpoint question in 06-13 from
"unbudgetable" into "N documents, ~X input tokens, proceed?".

**Precondition 1: a resolved `judge_instance`.** `EVAL-BUNDLE-V1.md` already settles the version
question and this plan does not re-litigate it: that document states verbatim that when a real judge
call is first made, "the resolved identity becomes part of the bundle's own **next-minted
version**, per §EV.1's own 'judge instance ... changing' invalidating-change rule — this document is
not re-edited in place to carry it retroactively." So the answer is **mint `bundle@v2`, never re-mint
v1**. Conveniently `mint_bundle` already does this by construction: its version identity is a content
hash over `judge_instance` among other members, so a changed judge identity mints the next version
automatically and `bundle@v1`'s bytes and checksum are never touched. What is missing is only the
*resolver*: `databasise/eval/remint.py`'s `resolve_judge_identity()`, which reads the identity a real
provider response reports and refuses to substitute the requested id — this project's
"hash what is installed, never what is declared" convention (Phase 1 D-12 / Phase 2 D-08), already
implemented once in `databasise/clients/openai_compat.py`.

**Nothing in this plan makes a live call.** Both entry points are proven against stub clients and
seeded fixtures. The single live judge call, and any real corpus ingest, sit behind 06-13's blocking
spend checkpoints. A `--spend`-flagged invocation and `remint.main()` are the artifacts 06-13 runs
*if* the owner authorizes; they are not run here.

Purpose: MACH-03 is Pending against exactly these two preconditions. Closing them spend-free is the
whole of what can be done without an owner decision.
Output: two new modules under `databasise/eval/`, two new test modules, no live call, no spend.
</objective>
