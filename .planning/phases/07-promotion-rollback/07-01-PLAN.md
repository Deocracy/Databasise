**`databasise/ledger/ledger.py` — four additive columns, each with exactly one meaning.** Extend `LedgerRecord` with `change_origin: str`, `record_kind: str`, `minted_version: str | None = None`, `targets_version: str | None = None`, and add the matching columns to the single `CREATE TABLE IF NOT EXISTS ledger` column list: `change_origin TEXT NOT NULL`, `record_kind TEXT NOT NULL`, `minted_version TEXT`, `targets_version TEXT`. No schema-alteration statement and no migration mechanism — the table holds zero rows in every environment (the module's own scope fence says nothing in the runner path calls `append()`), which is the identical situation the `alias` column addition was in.

Four columns, not the three RESEARCH.md sketched, and the reason is this module's own `alias`-column docstring: a field carrying two meanings can never be disentangled once real rows exist. `minted_version` means "the semver **this record mints**" and is NULL exactly when `record_kind == "tombstone"`. `targets_version` means "the semver **this record acts on**" and is non-NULL exactly for `record_kind` in `("rollback", "tombstone")`. Collapsing them into one column would make a tombstone's own version indistinguishable from a version it minted.

`change_origin` and `record_kind` are `NOT NULL` with no SQL default — an absent value must fail at the database, never fall back to a plausible string. Do not add them to `_JSON_FIELDS`; all four are scalar `TEXT`. Add the new fields to `append()`'s INSERT column list and its positional parameter tuple in the same order as the dataclass fields; `_row_to_record` already iterates `LedgerRecord.__dataclass_fields__` and needs no change.

Add one new derived projection beside `by_alias`, using the identical `ORDER BY id DESC LIMIT 1` shape and never a written column:

`generation_state(alias, version)` — the latest record naming the `(alias, version)` generation, whether it is the record that minted that version or a later record targeting it: `SELECT * FROM ledger WHERE alias = ? AND (minted_version = ? OR targets_version = ?) ORDER BY id DESC LIMIT 1`. Returns `None` when this alias has no such generation. 07-02's tombstone and unknown-version refusals are this method's only callers; it lands here so the projection set stays in one module. Add `CREATE INDEX IF NOT EXISTS ix_ledger_generation ON ledger(alias, minted_version)` alongside the existing two indexes.

Change `by_alias`'s WHERE clause to `WHERE alias = ? AND record_kind != 'tombstone'` and extend its docstring to say why: the active pointer derives from promotion and rollback generations only. A retirement record names a generation that has stopped being eligible; deriving the alias from it would resolve the alias to the very wiring that was just retired. This is a projection change, not a new mechanism — the ordering, the `LIMIT 1` and the derived-query discipline are untouched.

**`databasise/seam/promotion.py` (new) — pure computation, no I/O, no engine import.** Follow `selectors.py`'s shape: module constants plus pure functions over already-resolved wirings. Declare, all at module scope as literal constants:

`PROVENANCE_OPERATOR_ASSERTED = "operator_asserted"`; `CHANGE_ORIGINS = frozenset({"human_edit", "machine_mutation"})` — both accepted per D-08, because CONTRACT §7 makes `change_origin` orthogonal to provenance and the frozen contract is not re-litigated at the seam; `RECORD_KIND_PROMOTION = "promotion"`, `RECORD_KIND_ROLLBACK = "rollback"`, `RECORD_KIND_TOMBSTONE = "tombstone"`.

`resolve_single_arm(trace_records)` — takes the already-resolved trace-record dicts, collects the distinct `arm_id`/`wiring_id` values, and returns the one arm name they agree on. Raise `EmptyPromotionTraceIdsError` for an empty input and `DisagreeingPromotionTraceIdsError` when more than one distinct value is present. Never "take the first" and never "take the last" — a promote call whose trace ids belong to two different wirings is a caller mistake that silently promotes the wrong wiring if the disagreement is resolved instead of refused.

`declared_surface(resolved, registry)` — returns the pair `(frozenset(_wiring_effects(resolved, registry)), tuple(resolved.get("provides") or []))`: the union of every node's registered Part's own declared effects, plus the wiring's own `provides` list. This pair is CONTRACT §0's "declared socket / capability / effects surface" for the MAJOR/MINOR comparison. Reuse `selectors._wiring_effects` rather than re-deriving the union — it already applies CR-01 (the registered Part's effects, never the wiring node's possibly-narrower declaration).

`mint_version(prior_version, prior_surface, new_surface)` — returns `"1.0.0"` when `prior_version is None`; otherwise parses `prior_version` as three integers and returns `f"{major+1}.0.0"` when the two surfaces differ and `f"{major}.{minor+1}.0"` when they do not. **PATCH is never minted**; no branch of this function may return a version whose patch component is non-zero. Do not add a semver library — this is a two-branch integer bump over strings this module itself produces, and `pyproject.toml` carries no semver dependency today. Derive the prior version from the alias's prior **active generation** (`Ledger.by_alias`), never from a count of how many rows the mutation has ever accumulated: a rollback-then-repromote sequence would otherwise mint a number disconnected from the declared-surface rule §0 actually states.

`derive_mutation_class(new_node_ids, prior_node_ids)` — D-10's machine derivation, with the two node-id sets as module constants:

`_INDEX_RECIPE_NODE_IDS = frozenset({"embedder-index", "full-ingest", "chunk-embed", "openie", "entity-fact-embed", "fact-edges", "passage-edges", "synonymy-edges", "graph-augment-persist"})` — RIG §CM.1's index-extraction moment. `embedder-index` is PARTS §L.1's one LightRAG index-recipe node; `full-ingest` is LightRAG's `corpus-ingest.json` position; the remaining seven are exactly the node ids in `databasise/wirings/hipporag/corpus-ingest.json`. Confirm that seven-name list against that file rather than trusting this paragraph.

`_ANSWER_LEVEL_NODE_IDS = frozenset({"generate", "keywords", "fact-filter"})` — RIG §CM.1's query-generation moment: the prompt-bearing nodes whose registered Part declares `calls_llm` and which are not in the index recipe. `openie` also declares `calls_llm` but is index-side and is classed there; this is the one overlap and the index-recipe check runs first, so it resolves deterministically.

The rule: let `differing` be the symmetric difference of the two node-id sets, unioned with the node ids present in both whose `component` identity differs. If `differing` intersects `_INDEX_RECIPE_NODE_IDS` return `"index-side"`; elif it intersects `_ANSWER_LEVEL_NODE_IDS` return `"answer-level"`; else return `"retrieval-side"`. A first promotion passes an empty `prior_node_ids`, so `differing` is the wiring's own node-id set and the same rule classes it — D-10's own stated behaviour.

**`databasise/seam/engine.py` — `async def promote(self, alias, trace_ids, change_origin, *, verb="operator-asserted")`.** Follow `delete_document`'s refuse-before-any-write shape exactly. In order: refuse an invalid `change_origin`; refuse an empty `trace_ids`; resolve every trace id through `self._trace_store.resolve(...)`, letting `UnknownTraceReferenceError` propagate unwrapped; call `resolve_single_arm` to get the one arm name; resolve that arm via `databasise.wirings.resolve.resolve_arm`; read `Ledger(self.store_root).by_alias(alias)` for the prior active generation and resolve its `mutation_id` when one exists; derive the class and mint the version; construct the `LedgerRecord`; append it.

`verb` is accepted with its default in this task so the signature is stable across the three transports (D-04 rates the signature `costly` precisely because the conformance tests pin it) — Task 3 gives the non-default values their refusals. In this task, a non-default `verb` may raise `NotImplementedError` naming Task 3 as owner rather than falling through silently, exactly as 04-01 did for the unbuilt selector branches.

The record's fields: `mutation_id` = the resolved arm name; `mutation_class` = the derived class; `parent` = the prior active generation's `mutation_id` or `None`; `arm_instance_hashes` = the distinct `wiring_instance_hash` values read off the resolved trace records (real data from the runs the operator read — never fabricated, never returned to the caller); `effect_size`, `verdict`, `evidence_pointer`, `depth_label`, `tier_of_decision`, `decomposition_ratio` all `None` — RIG §PR.3's stated absences, filled with nothing; `opaque_ttl_renewals` and `parity_records` empty lists; `proposer_id = "operator"`; `promotion_provenance = PROVENANCE_OPERATOR_ASSERTED`; `promotion_trace_ids` = the caller's list; `alias` = the caller's alias; `change_origin` = the caller's value; `record_kind = RECORD_KIND_PROMOTION`; `minted_version` = the minted semver; `targets_version = None`.

One `INSERT` in one transaction **is** the atomic alias repoint, because the active pointer is a derived query — do not add a second write, a transaction wrapper around two statements, or any "update the current pointer" step. `Ledger` is synchronous by deliberate exception (its own WR-03 note); offload the append at this async call site with `await asyncio.get_running_loop().run_in_executor(None, lambda: ledger.append(record))` rather than making `Ledger` async.

Place it beside the existing seam response models and export it, plus `promote`, from `databasise/seam/__init__.py` alongside the existing exports.
