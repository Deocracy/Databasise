## Deviation from API-07's literal tool list, stated rather than silently taken

`API-07`'s requirement text names the set as `(ingest, query, delete, status, compare)`. This plan
ships `ingest`, `query`, `delete`, `status`, `resolve`. Two changes, each with a reason:

- **`compare` is deliberately absent.** The comparison operation is `API-08`, scheduled to Phase 6,
  and it exists behind no transport today. ROADMAP criterion 5 requires the MCP surface to expose
  *the same capabilities as REST*; a `compare` tool with nothing behind it would break that parity
  in the other direction and would be a stub, not a capability. Adding it when the operation exists
  is legal growth under §18.5 (a genuinely new operation earns a tool) and is recorded as such in
  this phase's `COVERAGE.md` operations table.
- **`resolve` is added.** Phase 4 shipped two operations REST exposes and API-07's literal list
  omits — evidence dereference and trace resolution. Without them an MCP client receives evidence
  references and a trace token it cannot follow, which is a real capability gap against REST. They
  are one intention ("follow this reference") and therefore one tool with a scope argument, not two
  tools; that is the selector-versus-tool test applied honestly rather than an excuse to grow.

Both are recorded in `COVERAGE.md`'s §18.5 operations table by plan 05-06 and must be reflected
there if this plan changes either.
