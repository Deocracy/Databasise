<objective>
Close gap G-05-1 (05-VERIFICATION.md's failed truth 6 / 05-REVIEW.md CR-02): make the corpus-side
write operations refuse on **any** node failure instead of only on the two exception types the
current check happens to enumerate.

Purpose: ROADMAP criterion 3 ("Caller uploads a document, polls the job to completion, then
deletes it") carries an implicit reliability guarantee that the job handle a caller polls belongs
to an ingest that actually ran. Today it may not: with the pinned v1 interpreter missing, the
verification pass observed `RETURNED (no exception): job_id=... enqueued=0` — a plausible-looking
handle for an ingest that never happened, with no signal a caller could act on.
Output: one shared refusal helper in `databasise/seam/engine.py`, both write call sites routed
through it, and two committed regression tests that reproduce the live failures the verification
pass reproduced by hand.
</objective>
