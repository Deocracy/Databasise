<assumption_delta_decision>
**Detected delta:** this phase turns one call path (`run_wiring`, imported in-process) into two
transports (in-process import and REST). That is a singular-to-plural transition.

**Resolution: `promote`, not add-alongside.**

- **Primary noun:** the seam object, `databasise.seam.engine.Databasise`.
- **Rationale:** both transports are adapters over the one seam object; neither is the seam.
  D-17 already fixes this, and criterion 5 is only provable if there is exactly one place where
  selector resolution, redaction and envelope assembly happen. Adding REST alongside the
  in-process path would create a second, drifting implementation of all three.
- **Invariant test (04-05, per D-17 and criterion 5):** both transports round-trip the same query
  object to the same envelope, field-by-field, excluding only the trace token and timing-derived
  values. That test is already required work, not extra work — the promote decision is what makes
  it meaningful rather than a coincidence.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| consumer → seam object | The query object is untrusted structured input; its members reach node configs, store queries and LLM prompts |
| seam → `run_wiring` | The redaction boundary. Internal identity (wiring id, arm id, node ids, instance hashes) exists on the machine side and must not cross outward |
| seam → registered parts | Query-object members become part config; a member no part declares a capability for must not reach a part at all |
