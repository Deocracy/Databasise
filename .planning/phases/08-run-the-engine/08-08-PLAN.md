Facts this plan relies on (RESEARCH Pitfall 6, reproduced with starlette 1.6.0):
- `allow_origins=[O]` alone answers the POST preflight with 400 "Disallowed CORS method" (Starlette's default `allow_methods` is GET only), so pass `allow_methods=["GET", "POST", "DELETE"]` and `allow_headers=["Content-Type"]`.
- A trailing-slash origin never matches the browser's Origin header; refuse it at validation.
- Route methods in `rest.py`: POST /query /compare /query/stream /evidence/resolve /trace/resolve /documents /documents/upload /promote /rollback /retire; GET /jobs/{id} /health /corpus /corpus/counts; DELETE /documents/{id}.
- `tests/seam/test_rest_transport.py` walks `rest.py`'s AST for forbidden calls (`ResponseEnvelope`, selector and redact names); `add_middleware` and a module-level validator are outside that set. Do not edit route bodies.
- GET /health calls `run_corpus_op` (a v1 subprocess); tests monkeypatch `databasise.seam.engine.run_corpus_op` the way `tests/seam/test_rest_corpus_endpoints.py::_patch_status_and_health` does.
- From plan 08-01: `serve_rest.build_parser()` and `serve_rest.build_app(args, clients)`.
</context>
