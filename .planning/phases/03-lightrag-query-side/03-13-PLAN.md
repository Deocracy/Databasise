<objective>
Close 03-VERIFICATION.md gap 2 (committed evidence is stale relative to source) and complete the
answer to gap 3 (no valid retrieval-level parity for the graph-half arms), then route gaps 1 and 4
— which no executor may close — to the owner in a form they can act on directly.

The staleness is structural, not accidental: `run_comparison` writes to
`databasise/parity/.comparison_results/{arm}.json`, while `parity_report` reads
`databasise/evidence/parity_results/{arm}-comparison.json`. The promotion between the two is a
manual copy. Three fix commits landed after the last promotion, so the committed records describe a
crash the source no longer produces. This plan does the run and the promotion together, once, so
the two cannot drift within it.

Gaps 1 and 4 are owner-only by contract, not by convenience. CONTRACT §5 requires a human-reasoned
cause for a named excursion, and criterion 6 requires a human read of answer substance. The
mechanism for both already exists and is tested (plan 03-10). What is missing is the human. This
plan makes the ask exact and leaves it unanswered.

Purpose: the phase's central claim is "parity is measured, not asserted." Evidence that describes
code which no longer exists is an assertion; a zero produced by both sides retrieving nothing is an
assertion; an AI-authored cause presented in a file named for human findings is an assertion. This
plan removes the first two and names the third for its owner.
Output: one consistent evidence set describing the code at HEAD, and two precisely worded owner
tasks.
</objective>
