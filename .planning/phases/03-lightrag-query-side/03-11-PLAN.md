<objective>
Close the upstream half of 03-VERIFICATION.md gap 3: the graph-half arms have no valid
retrieval-level parity because **there is nothing in the graph to retrieve on either side**.

The recorded `KeyError: 'entity_name'` / `KeyError: 'src_id'` stop reasons are a downstream
symptom. The cause, reproduced on this machine during planning, is one unquoted line in the
runtime parity env file:

`v1/parity-env.txt` sets `OPENAI_LLM_EXTRA_BODY` to a JSON object written without surrounding
quotes. `v1/README-PARITY.md` instructs the operator to load it with `set -a && . .env.parity`,
and bash's quote-removal on an assignment strips the inner double quotes, so the process sees
`{provider:{order:[Alibaba],allow_fallbacks:false}}`. `_extra_body()` in
`v1/scripts/run_parity_ingest.py` calls `json.loads` on that and raises
`JSONDecodeError: Expecting property name enclosed in double quotes: line 1 column 2 (char 1)` —
byte-identical to the `error_msg` recorded against all 20 documents in
`v1/.parity_working_dir/kv_store_doc_status.json`, every one of which is at status `failed`.

The chunk-embedding path never calls `_extra_body`, which is why the chunk index is populated
(and why `naive`/`bypass` produced real numbers) while `faiss_index_entities.index.meta.json`
and `faiss_index_relationships.index.meta.json` are both two bytes — an empty object. The
importer then correctly imported nothing for those two kinds: `v1/.parity_v2_store/shared-*/`
holds `chunks`, `text_chunks`, and `chunk_entity_relation` and no `entities` or
`relationships` directory at all.

The same defect also means the D-07 provider pin was never applied to any ingest call. A second,
independent asymmetry is fixed here: `run_arm._build_clients` never passes the pin to the
decomposed arm's client at all, while `v1_driver_script.py` does pass it to the original arm —
so provider routing is currently an unpinned axis in the very comparison D-07 exists to pin.

Purpose: without extracted entities and relations there is no graph-half retrieval to measure,
and every downstream fix (plan 03-12) and re-run (plan 03-13) would re-measure the same vacuum.
Output: a corpus index that actually contains a knowledge graph, a re-run that cannot silently
report success over a wholly failed extraction, and two arms configured from one pinned record.
</objective>
