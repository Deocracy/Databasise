<objective>
Close the downstream half of 03-VERIFICATION.md gaps 2 and 3.

`databasise/parity/run_arm.py`'s `_build_stores` binds exactly one vector store — the `chunks`
namespace — under the single key `"vector"`. `CapabilityScopedStores` maps the `reads_vector`
effect to that one key, so `entity-lookup`, `relation-lookup`, `chunk-vector` and `chunk-sel-kg`
all receive the same chunks index. `entity-lookup` therefore returns chunk records, whose v1
`meta_fields` are `full_doc_id` / `content` / `file_path` and contain no `entity_name`; the
records reach `entity-hydrate-expand` and produce the recorded `NodeExecutionError: 'entity_name'`.
`relation-lookup` produces the `'src_id'` counterpart the same way.

Commit 1827695 (CR-01) stopped the crash by routing such a record to `missing_seeds` — correct
defensive behaviour that must stay — but it does not put an entity in front of the node. This plan
does: each vector-reading position reads the namespace it is actually defined over.

Plan 03-11 is what makes this measurable — before it, the `entities` and `relationships`
namespaces did not exist on disk at all.

Purpose: without this, the graph-half arms retrieve chunk records or nothing, and any re-run
would re-measure a vacuum with a tidier error message.
Output: correct per-namespace reads, a refusal that makes the wrong namespace unreachable, and one
graph-half arm proven end to end before plan 03-13 spends a full five-arm run.
</objective>
