<decisions_recorded_here>

**DEC-A — the allowance is `config.token_allowance`, an ordinary int field on the metered node's
own wiring `config` object.** `<reversibility rating="reversible">` A config key name and one
read; no stored state, no data migration, no schema change. `runner/budget.py`'s module docstring
already establishes exactly this convention for `ApportionmentPolicy`
("carried as an ordinary field inside that node's own wiring `config` object
(`config.apportionment_policy`), so `identity.canon.config_hash` already covers it as part of that
node's own config, verbatim, with no separate identity mechanism minted here"). `token_allowance`
follows that established pattern verbatim, so it is covered by `config_hash` for free and mints no
new identity mechanism. Consequence, and it is intended: two wirings differing only in a node's
allowance are two identities, exactly as CONTRACT §9's merge-side apportionment repair already
requires for the apportionment policy.

**DEC-B — an absent `token_allowance` means an allowance of 0, not an unbounded one.**
`<reversibility rating="reversible">` A module-level constant; reversing it is a one-line change.
Grounded, not chosen by taste: CONTRACT §9 states a budget is "a splittable capability token" and
that "a branch cannot spend what it was not handed." A node handed no allowance was handed zero.
This is the same deny-by-default posture as CONTRACT §2's "MUST refuse at wire time any behaviour a
part did not declare" and avoids inventing a magic default ceiling. Blast radius is small and
loud, never silent: a node that declares none of `calls_llm`/`calls_rerank`/`calls_embedding`
accrues spend 0 and therefore stays `within_budget` against a 0 allowance, so every currently-wired
node in every existing test is unaffected; only a node that really does declare a calling effect
and really does spend is affected, and it is then traced as a first-class `budget_halt` partial run
(CONTRACT §9's "MUST be traced ... MUST NOT be discarded"), never discarded and never raised.
Verified: `FAKE_LLM_CALLER_PART` is the only part declaring `calls_llm` and it is currently never
wired through `run_wiring` in any test — it is only invoked as a bare body in
`tests/parts/test_reference_parts.py` and `tests/runner/test_run_record.py` — so DEC-B breaks no
existing test.

**DEC-C — post-hoc metering at the node boundary is the correct granularity for Phase 1, and the
scope fence is recorded rather than left implicit.** `<reversibility rating="reversible">`
RIG §LC.1 says "the first spend that would exceed capacity halts before that spend is made." That
sentence governs a running cumulative budget across a node's *internal* calls. CONTRACT §9's V-7
repair puts exactly that inside the node's own boundary — "a node's own internal parallelism ... is
its private implementation detail; the machine meters and can halt the node only at its declared
boundary." So the machine layer meters each node's aggregate spend once, at its declared boundary,
after its body returns; it does not pre-authorise individual internal calls. `meter()` already
implements RIG §LC.1's threshold direction exactly (`spent <= allowance` is `within_budget`, so
landing on the ceiling continues). Recorded here so a later reader does not mistake the granularity
for an oversight.

**DEC-D — the CR-01 `kind`-vs-`effects` narrowing recorded in `01-REVIEW-FIX.md` is ACCEPTED, with
one addition.** `<reversibility rating="reversible">` `01-VERIFICATION.md`'s second `missing:`
bullet asks for a `parse_wiring` check that "`node.kind` is consistent with `part.kind`";
`01-REVIEW-FIX.md` deliberately scoped the new check to `effects` only. That narrowing is sound:

1. The security property is already unconditional without it. `execution_mode` — the only consumer
   of a `kind` value in any enforcement path — is derived from `part.kind` at
   `runner/scheduler.py:252`. An attribute scan of the package outside `databasise/tests/` finds
   ZERO reads of a wiring node's `kind` in any module. A consistency check on a field no
   enforcement path reads would close no bypass; it would be pure hygiene.
2. A strict check would break a deliberate, documented, pre-existing convention. `WiringNode.kind`
   is an unconstrained `str` whose own docstring in `databasise/parts/schema.py:12-17` defers
   structural-kind dispatch to a later plan; `tests/validator/test_taint_conformance.py`'s 12-case
   table sets `WiringNode.kind="primitive"` uniformly against fixture Parts of kind
   `stage`/`opaque`/`evidence`; and `tests/test_phase_success_criteria.py`'s module docstring
   documents the wiring-position-kind decoupling explicitly.

The addition: because the entire argument rests on the claim "no enforcement path reads a wiring
node's `kind`", that claim is pinned by an AST-based structural test (Task 3) rather than left as a
prose assertion a future phase could silently invalidate — which is exactly how the `resumable`
