production-quality end-to-end tracer slice through every layer this phase will touch: a wiring JSON
is parsed, its parts resolve from the in-code registry, its effective depth is computed, its nodes

fails here — after one slice, not after seven layers are already committed.

identity decisions (D-12, D-09) confirmed by the developer and implemented in the hash they

<decisions_recorded_here>
Three items CONTEXT.md left to Claude's Discretion, plus the two Open Questions 01-RESEARCH.md
raised, are decided in this plan and written into the package itself so no later plan re-opens them:

- **Python floor: `requires-python = ">=3.11"`.** `databasise/` sets its own floor, higher than
  `v1/pyproject.toml`'s `>=3.10`, so the runner can use stdlib `asyncio.TaskGroup` rather than
  adding `anyio` as a dependency purely to preserve a 3.10 floor nothing in this phase needs. This
  is legitimate precisely because D-14 makes `databasise/` a separate package that need not inherit
  v1's floor. (01-RESEARCH.md Open Question 1.)
- **Build config: `databasise/` is a fully independent package, not a `uv` workspace member shared
  with `v1/`.** Its own `databasise/pyproject.toml` and its own lock file. Rationale: D-14 forbids
  any import path from `databasise/` to `v1/`, and a shared workspace would put v1's server-backed
  dependency set (Neo4j, Milvus, Qdrant, asyncpg, OpenSearch, the React build chain) on
  `databasise/`'s resolution graph — making EMBED-01's "no external DB servers" claim a property of
  a resolver decision rather than a property of the dependency list. Independent means the
  dependency list is itself the proof. (01-RESEARCH.md Open Question 2.)
- **Structured-concurrency mechanism: `graphlib.TopologicalSorter` for readiness bookkeeping plus
  one `asyncio.TaskGroup` per ready batch.** No orchestrator, no external scheduler, no metadata DB.
- **RFC 8785 canonicalisation: `rfc8785==0.1.4`.**
- **The node config field carrying D-09's semaphore size is `config.max_concurrency` (integer,
  minimum 1).** Placing it inside the node's own `config` object means it enters `config_hash` by
  construction rather than by a special case a later reader could forget.
</decisions_recorded_here>

  <options>
    <option id="option-a">
      <name>D-12 as written: resolved closure from importlib.metadata (RECOMMENDED — this is the locked decision)</name>
      <pros>Hashes what is actually installed, never what a lockfile declares. CONTRACT §1 names the declared-closure alternative as the exact skew the environment hash exists to kill.     runs under different settings. Putting the cap inside `config` makes that automatic; putting it
    outside makes it something a later step must remember to record. D-09 goes beyond CONTRACT §9's
    V-7 minimum deliberately for exactly that reason. Task 5 implements this; every `config_hash`
    computed from that commit forward carries it.
  </context>
