Facts this plan relies on (HEAD after 10-10, verified while planning):
- `stores/vector.py`: results are built as `{"id": ..., "score": ..., **entry["metadata"]}` in `query`, `score_all` and `self_knn`, and as `{"id": doc_id, **entry["metadata"]}` in `get_by_id`, so metadata `id`/`score` overwrite the real values (ST-07). `upsert`'s existing length checks raise plain `ValueError` before `_pending` is touched (about 153-170). `query` returns `[]` for an empty index before searching, and `top_k=0` reaches a faiss `AssertionError` (research Pitfall 13, verified live). `self_knn(*, top_k)` uses `top_k + 1` neighbours.
