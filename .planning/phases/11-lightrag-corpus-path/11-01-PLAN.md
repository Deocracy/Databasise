<objective>
Tracer plan for the phase. A document ingested through the seam's LightRAG path lands in a per-workspace v1 working dir and is mirrored into the v2 stores the query arms read, and a delete removes it from both (D-01, M-04 option b). The new opaque part `lightrag/v1-index-sync@0.1.0` runs as the second node of `corpus-ingest.json` and `corpus-delete.json`. It reads v1's committed index with the readers split out of `parity/import_index.py` and writes only through `ctx.stores`, so Phase 10's prepare-all/commit-all and drop-on-failure cover it.

Purpose: ROADMAP Phase 11 criterion 1 (SC1). This is the slice that proves the architecture: v1 subprocess, then an in-process mirror, then one atomic v2 commit, then a query and an evidence resolve. Every later plan builds on it.
Output: the hermetic real-driver harness, the sync part and its admission record, the readers refactor, the per-workspace dir plumbing, the two-node corpus wirings, ingest seam events, and the LRAG-02 proof.

Scope notes:
- The per-workspace dir changes only part bodies and the engine, not any opaque part's effects, verdicts or driver protocol. The driver already reads `job["working_dir"]`. So nothing here needs the D-06 version bump; 11-03 carries it.
- `run_corpus_op`'s `working_dir` keyword cannot become required: the protected `tests/seam/test_rest_corpus_endpoints.py` stub bodies call `run_corpus_op` without it. Instead the repo-global default constant is deleted, and the job carries `working_dir` only when the caller passes one. The real driver reads `job["working_dir"]`, so a production caller that forgets it fails loudly (exit 1). It never falls back to the operator corpus.
- Files per plan: 16 files across 2 tasks, accepted because a tracer touches every layer once (adapter, engine, parts, readers, wirings, harness); the calibrated estimate (50k) is inside budget.
- The real-driver proofs here are not env-gated: their only skip is `requires_v1` (v1/.venv/bin/python absent). Task 2 replaces the old `DATABASISE_RUN_REAL_DELETE` gated proof, and no test in this plan reads that flag or any other env switch.
- Research Pattern B pruned `v2 ids - v1 ids` over the whole v2 namespace. That would delete a parity-imported corpus on the first seam write into a populated store root (the launcher's default root is one). This plan prunes over a mirror manifest instead: one kv record listing the ids the sync wrote last time, committed atomically with the rows. It is still a set difference per namespace (CONTEXT discretion item), and parity rows are never touched.
</objective>
