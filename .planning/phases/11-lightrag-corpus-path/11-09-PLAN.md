Facts this plan relies on (verified while planning):
- `seam/engine.py` `health` (1258-1293 at HEAD): probes `_HEALTH_PROBES` read-only in `asyncio.to_thread`, then calls `run_corpus_op("health", ...)` and reads `working_dir_present` / `storages_initialized`. Any exception forces both false. `ok` requires every store `ok` and every engine value true; clients never affect status.

- Protected tests that read health: `tests/seam/test_health_probe.py` (fresh root creates nothing, stores absent or corrupted or busy, status degraded; it imports `_make_fake_run_corpus_op` from the unprotected `tests/seam/test_corpus_status.py` and calls it with no arguments), `tests/seam/test_corpus_adapter_failures.py` (200 'degraded' on any adapter failure), `tests/seam/test_rest_corpus_endpoints.py` (REST health equals in-process health), `tests/launcher/test_launchers.py` and `tests/seam/test_rest_cors.py` (status code 200 only).
