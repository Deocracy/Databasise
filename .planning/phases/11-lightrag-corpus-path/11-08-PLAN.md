<objective>
A timed-out ingest leaves its document in a visible interrupted state, with an explicit retry action, and the next unrelated ingest does not reprocess it (LRAG-07, G-33, D-08). The driver halves landed in 11-03: the targets filter and `retry_doc_ids`. This plan adds the seam halves: the interrupted label, the retry route and MCP tool, and the named refusal.

Purpose: ROADMAP criterion 3's "a timed-out ingest leaves its document in a visible stuck/interrupted state with an explicit retry action".
Output: the remap in `corpus_status` and `document_counts`, `Databasise.retry_document`, `POST /documents/{document_id}/retry`, the `retry` MCP tool, `DocumentNotInterruptedError`, the §18.5 COVERAGE row, the granted growth-pin edit, and the real-driver proof.

D-08's fallback amendment is not needed. Research Finding 2 proved the driver-side filter restricts processing to named ids, so LRAG-07's clause "the next ingest does not reprocess it" holds as written and REQUIREMENTS.md gets no exception clause.

Scope choice: `get_job_status` reports v1's raw status. A job id names one run, and "interrupted" is a corpus-level view of a document that no run holds. The protected RUN-10 round trip (`tests/seam/test_rest_corpus_endpoints.py`) polls `/jobs` through a synthetic pending, processing, processed sequence with no write in flight, so remapping `/jobs` would break a ledger test without a requirement asking for it. Record this in the `corpus_status` docstring.
</objective>
