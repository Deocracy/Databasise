Port v1's Cozo graph adapter and Faiss vector adapter into `databasise/stores/`, by deliberate copy
with recorded provenance, adapted to the per-namespace directory layout and the shared lifecycle
contract.

defaults and the Phase 3 parity baseline. Swapping either while decomposing the query side would
confound the parity measurement, so a later change means re-running parity, not editing a config
value. The port has to carry v1's hard-won mitigations rather than re-deriving them.

Output: two embedded store adapters with the four Cozo frozen-bug mitigations enforced by a
regression suite running against the new code.

    exact v1 source path, per CONTRACT §7 and D-14, and do not present the copied design as
    originally authored here.

    Carry three properties from the v1 implementation:

    First, the deferred-embedding pending buffer: documents awaiting embedding are held in a
    pending-document structure before they enter the index, mirroring the Cozo adapter's buffer
    discipline so both backends present one commit/abort contract to the runner.

    Second, the raise-don't-silently-drop rule. An embedding-count mismatch, an index-add failure,
    or a sidecar write failure raises before any mutation lands; the pending buffer stays intact so
    nothing is partially written. This is the house style CONTEXT.md states directly — refusals over
    silent fallbacks — and it is what makes a mis-paired vector impossible rather than merely
    unlikely.

    Third, the metadata sidecar: the Faiss index and a separate metadata file are written together
    or neither commits. Both live inside the same namespace directory as the KV, lexical, blob and
    Cozo stores, so success criterion 4's `ls` check shows one directory per namespace containing
    every store that namespace owns.

    Use an exact inner-product index over normalised vectors for cosine similarity, matching v1's
    incumbent behaviour — Faiss is the Phase 3 parity baseline, so the index type is part of the
    baseline and not a free choice. There is no fallback vector store: `nano-vectordb` is not part
    of this stack, and a failure to load Faiss is an error naming Faiss, never a degraded path onto
    something else.

    Implement the same five-method lifecycle ABC as every other adapter.
