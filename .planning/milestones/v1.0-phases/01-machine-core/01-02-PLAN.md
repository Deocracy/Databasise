<objective>
Drive ONE production-quality end-to-end tracer slice through every layer this phase will touch: a
wiring JSON is parsed, its parts resolve from the in-code registry, its effective depth is computed,
its nodes receive real instance identities, the runner executes them under structured concurrency
with a per-node semaphore, one node writes to the embedded SQLite KV store, and a run record is
stamped and validated against the frozen `rig-trace.schema.json`.

Purpose: prove the architecture end-to-end on one commit before seven horizontal expansion plans
build on it. If the seam between identity, depth, the runner and the trace schema does not hold, it
fails here — after one slice, not after seven layers are already committed. This plan runs **alone in
wave 2**, between the scaffold in wave 1 and the four expansion plans in wave 3, precisely so the
slice that de-risks them is verified before any of them starts.

Output: a green end-to-end test, plus the two one-way identity decisions (D-12, D-09) — selected by
the developer in plan 01-01 — implemented in the hash they permanently define.
</objective>

  <action>
    Build the thinnest real path through every layer. This is production code that stays, not a
    prototype: stubs are permitted only where a later plan can fill them without changing the
    architecture. Functionality gaps are acceptable; architectural gaps are not.

    `databasise/identity/env.py` — implement `environment_hash() -> str`, memoised per process with
    `functools.cache`. It collects: `sys.version_info[:3]` as a list, `platform.platform()`, and for
    every distribution returned by `importlib.metadata.distributions()` a triple of
    `[metadata["Name"], version, record_digest]`, where `record_digest` is a SHA-256 over that
    distribution's sorted RECORD hash lines and is `None` where RECORD is absent. Sort the
    distribution list by name. Canonicalise the whole object with `rfc8785.dumps` and SHA-256 it.
    Nix store paths are never read and never included. Record plan 01-01's Task 3 selection verbatim
    in this module's docstring, together with the D-12 rationale that this hashes what is installed
    and never what a lockfile declares.

    `databasise/identity/canon.py` — implement `canonicalise(obj) -> bytes` wrapping
    `rfc8785.dumps`, and `config_hash(node_config: dict, env: str | None = None) -> str` returning
    `hashlib.sha256(canonicalise({"config": node_config, "environment": env or environment_hash()})).hexdigest()`.
    The author-supplied `node_config` goes in verbatim and is never normalised, defaulted or
    reordered by this module — CONTRACT §1 forbids hashing a tool's normalised output. Raise a
    named `CanonicalisationError` on any integer outside the int64 range rather than letting it
    through. Document in the module docstring that RFC 8785 collapses the int/float distinction so
    `1` and `1.0` hash identically, and that key ordering is by UTF-16 code unit per JCS, not by
    code point and not by locale.

    `databasise/identity/instance.py` — implement
    `instance_hash(name_at_version: str, config_hash: str, resolved_dependency_ids: list[str]) -> str`
    as SHA-256 over `canonicalise([name_at_version, config_hash, sorted(resolved_dependency_ids)])`.
    Also implement `cache_partition_key(name_at_version, config_hash, resolved_dependency_ids, declared_input_values)`
    as SHA-256 over the canonicalisation of exactly those four members and nothing else — per §1's
    cache-partition-key clause, no field outside the tuple plus declared inputs may enter it.
    Neither function accepts a node id; document in the docstring that a wiring node id is a
    position, never an identity.

    `databasise/parts/schema.py` — define the `NodeKind` tagged sum as a pydantic v2 discriminated
    union keyed on a single `kind` field, with the five structural kinds `fanout`, `join`,
    `fixpoint`, `subgraph`, `opaque` present as members. Define `Effect` as a `Literal` over exactly
    the seventeen frozen members: `reads_kv`, `reads_vector`, `reads_graph`, `reads_lexical`,
    `reads_blob`, `writes_artifact`, `calls_llm`, `calls_rerank`, `calls_embedding`, `net`, `fs`,
    `self_storage`, `mutates_store`, `writes_kv`, `writes_vector`, `writes_graph`, `writes_lexical`.
    Define `Depth` as a `Literal` over `opaque`, `evidence`, `stage`. Define a `Part` dataclass
    carrying `name_at_version`, `kind`, `structural_depth`, `effects`, `upstream_ref` (nullable,
    per CONTRACT §7), and an optional `body` callable. Define a `WiringNode` model with fields
    `component`, `kind`, `effects`, `config` (default absent, not defaulted to an empty dict — see
    the canon docstring rule), and `deps` (list of node ids, default empty list).

    `databasise/parts/registry.py` — implement `PartRegistry` as an explicit in-code dict mapping
    `name@version` to a `Part`, per D-13. No `importlib.import_module` fallback and no
    `entry_points` discovery — that is exactly the extensibility D-13 rejects for this milestone.
    Provide `get(name_at_version) -> Part` raising a named `UnknownPartError` whose message quotes
    the requested key and lists the registered keys. Register two parts for the tracer: a
    passthrough part at `stage` depth with empty `effects`, and a KV-writer part at `stage` depth
    declaring `writes_kv`.

    `databasise/validator/parse.py` — implement `parse_wiring(doc: dict) -> ParsedWiring` doing one
    pass that accumulates every violation with a JSON-Pointer path rather than raising on the first,
    and returns them together. For the tracer the checks are: every `component` resolves in the
    registry, every entry in `deps` names a node present in `nodes`, and every declared effect is a
    member of the seventeen. Return a `ParsedWiring` carrying the typed nodes, the `deps` mapping,
    and the load-frozen snapshot the runner reads — CONTRACT §11 forbids mid-run reads of mutable
    decision state, so the runner must receive a frozen structure.

    `databasise/validator/depth.py` — implement `effective_depth(parsed) -> dict[str, Depth]` as the
    taint rule: a node's effective depth is the minimum over its own structural depth and the
    effective depth of every transitive dep, ordered `opaque < evidence < stage`. For the tracer,
    implement the acyclic case with `graphlib.TopologicalSorter.static_order()`. Leave the
    cycle-safe Tarjan SCC condensation to plan 01-03, but structure this function so that swapping
    the ordering source for a condensation DAG changes only where the order comes from, not the
    min-reduce itself — that is the architectural seam plan 01-03 fills. Also implement
    `derive_execution_mode(effects, kind) -> str` returning one of `in-process`, `subprocess`,
    `confined-unit`, `long-lived-service`, derived from declared effects per CONTRACT §3 (only pure,
    non-iterative nodes may be hosted in-process), never requested by the component; the tracer's
    two nodes must both derive `in-process`.

    `databasise/stores/base.py` — define the storage lifecycle ABC reproducing v1's shape by copy
    (not import): async `initialize`, `finalize`, `index_done_callback` (commit), and
    `drop_pending_index_ops` (abort), plus `drop`. Every store adapter in this phase shares it, so
    the runner has one commit/abort contract regardless of backend. Set `upstream_ref` to the v1
    source path in the class docstring per D-14 and CONTRACT §7.

    `databasise/stores/kv.py` — implement `SqliteKVStore` over stdlib `sqlite3`, one database file
    per namespace directory under the caller-supplied store root (D-06, D-07). Reproduce v1's
    `BaseKVStorage` method signatures by copy: async `get_by_id`, `get_by_ids`, `filter_keys`,
    `upsert`, `delete`, `is_empty`. Buffer writes in memory and flush on `index_done_callback`, with
    reads consulting the buffer first (read-your-writes before flush) — the same discipline the Cozo
    adapter needs in plan 01-06. A failed write raises; it is never logged and continued.

    `databasise/runner/scheduler.py` — implement
    `async def run_wiring(parsed, registry, stores, *, determinism_setting, concurrency_setting) -> dict`.
    Drive readiness with `graphlib.TopologicalSorter`; on `graphlib.CycleError` return the cycle as
    data under a `cycle` key rather than propagating the exception, because cyclic wirings are legal
    content. For each ready batch, sort the batch by node id before dispatch so two runs of the same
    wiring produce the same dispatch order, then run the batch inside one `asyncio.TaskGroup`. Each
    node's body runs under its own `asyncio.Semaphore` sized from that node's
    `config.max_concurrency` (default 1 when absent), created per node per run and never shared
    across nodes — a process-wide cap is rejected by D-11, and no module-level singleton, manager
    object or global limits dict may exist in this module. Record plan 01-01's Task 4 selection
    verbatim in this module's docstring, together with the D-11 rejection rationale that one arm's
    fan-out must never throttle an unrelated arm.

    `databasise/runner/trace.py` — define a `RunRecord` dataclass and a `NodeTrace` dataclass whose
    fields are exactly the run-level and per-node field sets in `rig-trace.schema.json`, including
    the nested `TokenAccounting` object with its five members. Provide `RunRecord.to_dict()`
    emitting a plain dict the schema validates. For the tracer, populate every required field with a
    real value where the tracer can produce one and with a schema-valid, explicitly-marked
    placeholder where the producing mechanism lands in a later plan — `bundle_ref` and
    `corpus_snapshot_hash` have no eval bundle until Phase 2, so emit a documented sentinel string
    rather than omitting the field and failing the schema. `arm_execution_order`, `cache_hit`,
    `guards_fired`, `realised_budget_share`, `determinism_setting` and `concurrency_setting` are
    D-10's gate-read fields and must carry real values from this commit forward, not placeholders.

    `databasise/__init__.py` — export the public entry point `run_wiring(wiring_doc, *, store_root,
    registry=None, determinism_setting, concurrency_setting)` that composes parse, depth, identity,
    scheduler and trace into one call, alongside the `__version__` plan 01-01 already put there.
    This is the seam every later plan and every consumer calls; keep it small.

    `databasise/tests/fixtures/wiring-tracer.json` — a two-node wiring: node `pass` using the
    passthrough part with no deps, and node `store` using the KV-writer part with
    `deps: ["pass"]` and a `config` object containing `max_concurrency: 2` and one other scalar the
    byte-change tests can mutate.
