    - Test 4 (key-order insensitivity): `{"a": 1, "b": 2}` and `{"b": 2, "a": 1}` produce the same
      digest, because JCS sorts keys.
    - Test 5 (JCS key ordering is by UTF-16 code unit): a config with two keys chosen so that
      UTF-16 code-unit order and Unicode code-point order disagree — a key in the Basic
      Multilingual Plane above U+E000 versus a key outside the BMP requiring a surrogate pair —
      hashes to the digest implied by UTF-16 ordering, and a hand-computed expected digest is
      asserted as a literal so a future canonicaliser swap cannot silently change the answer.
    - Test 6 (no Unicode normalisation): a string in NFC form and the same string in NFD form
      produce different digests. Canonical equivalence is not byte equality and RFC 8785 does not
      normalise.

      key is absent entirely produces a different digest from one whose `config` is `{}`. The rule

      normalised form; the test asserts inequality in both directions.
