Close G-03-1: the first completed five-arm parity comparison landed real numbers, and the evidence renderer cannot turn them into a document.

Two connected defects, both in `databasise/evidence/parity_report.py`:

1. `_collect_deviations()` hardcodes `cause=""` for every excursion it finds on a `status="completed"` record. `render_deviations_markdown()` then raises `UnreasonedDeviationError` and the whole render aborts — `PARITY-EVIDENCE.md` is currently 0 bytes on disk. There is no input path by which a human can supply a per-excursion cause, and hand-editing `DECLARED-DEVIATIONS.md` is not one: the document is renderer-owned and overwritten on the next render (03-REVIEW-FIX.md, CR-01).
2. Every prose section hardcodes the environment-precondition-refusal narrative written when no run had happened. That narrative is now false: all five arms are `completed`, hybrid/local/global carry `symmetric_difference=0` on chunks, entities and relations, all five storage audits ran to completion clean, and the N=5 keyword variance bands are real with `any_cache_served=false`.

The refusal itself is the point of the machinery and is not being weakened. CONTRACT §5's parity-not-gain rule and the `_GENERIC_CAUSES` absorber-category refusal both survive intact; what this plan adds is a committed, human-authored input file the renderer reads, so a *specific* cause can be supplied, survives re-render, and is checked against the measurement it was written for.

Purpose: criterion 2 and criterion 6 (D-10's deterministic retrieval-level gate) are satisfied by the owner *reading* an evidence document, not by a harness that could produce one. Right now there is no document to read.
Output: a rendering evidence pair produced from the completed run, a named cause for the two naive-arm excursions, a landing place for the still-pending human answer spot-check, and a reconciled MODAL-01 tracking entry.
</objective>
