    Write `databasise/parity/import_index.py` implementing D-01's one-time import and D-02's three
    assertions as one module with two entry points: an importer and a verifier, plus a `main()`
    following `databasise/tools/check_import_boundary.py`'s exit-code convention (collect
    `Violation`-shaped records, print one line each, exit 1 if any exist, exit 0 clean).

    The import mechanism is read-and-reinsert, not file copy — the two Faiss sidecars are different
    shapes (v1 stores an `_id_to_meta` dict; the v2 store stores `next_int_id` plus `entries` plus an
    `index_checksum`), so copying the pair would leave a v2 store that refuses to load. Read v1's
    index with `faiss.read_index`, pull each stored vector out by its integer id, pair it with its
    chunk id from v1's `.index.meta.json`, and write the batch through
    `FaissVectorStore.upsert(ids, embeddings, metadatas)` — the v2 store's precomputed-embedding
    path. This satisfies "copy vectors verbatim, never recompute": nothing re-embeds any text.
    Note in the module docstring that both stores L2-normalise on write, so re-normalising an
    already-normalised vector is idempotent and does not change the stored value — state this,
    because it is the reason the vector-set hash comparison is meaningful rather than trivially true.

    Import v1's chunk KV state into `SqliteKVStore` and v1's Cozo graph nodes and edges into
    `CozoGraphStore` through their public `upsert` methods, under the namespace
    `databasise/namespaces.py` derives, one store directory per namespace (Phase 1 D-07). Call each
    store's `index_done_callback` so the writes are flushed before verification reads them.

    The verifier runs the three D-02 assertions and returns a three-state result — `verified`,
    `inconclusive`, or `refused` — never a bare boolean: (a) chunk text byte-identical between v1's
    KV and the v2 KV primitive, compared per chunk id with the first mismatching id named;
    (b) the SHA-256 over the sorted `(id, vector-bytes)` pairs equal on both sides; (c) the graph
    node count, edge count, node id set, and edge endpoint-pair set all matching. A failed assertion
    yields `inconclusive` carrying the failing assertion and the offending id — PITFALLS 8's own
    prescription, and this codebase's stated refusals-over-silent-fallbacks style. The verifier never
    returns a pass or fail verdict on a failed precondition, because a confounded comparison that
    looks settled is worse than one that looks unsettled.
