<objective>
Fix the one filed code defect that refused 06-13 Task 1's real, spend-incurring HippoRAG index
build, at its actual root cause rather than at the node the traceback happened to name.

**The root cause is not inside `fact_score.py`.** `databasise/parity/build_hipporag_index.py` calls
`load_wiring("hipporag")`, which loads `databasise/wirings/hipporag/base.json` — all **thirteen**
node positions, including the six the base wiring itself declares under `consumes_query`
(`fact-score`, `reset-vector-join`, `dpr-fallback`) and their downstream `fact-filter` / `ppr` /
`assemble-result`. `fact-score` declares `deps: []`, so the scheduler dispatched it in the very
first ready batch alongside `chunk-embed`, with no query anywhere in its config. Its
`str(config.get("query", ""))` therefore evaluated to the empty string, and
`embed([""])` reached the provider and came back a `400 too_small`. 06-10 already built the
correct wiring for this job — `databasise/wirings/hipporag/corpus-ingest.json`, the seven
index-side positions, declaring `consumes_documents: ["chunk-embed"]` and the *identical*
`store_namespaces` the base wiring's query side reads. The harness simply never used it.

**The guard is the second half, at the one place every caller routes through.** Seven call sites
reach `ctx.clients["embedding"].embed(...)`, three of them with an unguarded
`str(config.get("query", ""))`, and one (`entity_fact_embed`) with a list that is empty whenever
OpenIE extracts nothing. Patching the one path the ticket names would leave every sibling still
capable of the same opaque provider 400. One named refusal in `OpenAICompatibleClient.embed` — the
single method all seven route through — turns the whole class into a diagnosable refusal.

**No fabricated outcome, no run.** This plan performs no live call and produces no measurement. It
closes `.planning/WINDOWS.md` entry id 3 and unblocks 06-15's re-attempt; it does not flip
MODAL-05.

Purpose: 06-VERIFICATION.md gap 1's first `missing` item — a fix so a real index build against a
real corpus can complete and be verified rather than refused.
Output: an index build that dispatches only index-side positions, a named empty-input refusal at
the client boundary, regression tests for both, and a closed ledger entry.
</objective>
