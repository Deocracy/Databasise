<objective>
Expand the proven promote slice into the other two operator verbs: `rollback()` to an explicitly
named semver, and `retire()` as a tombstone on the same append-only path — plus the rule that makes
SC1's "tombstoned losers are never lifted" real in production rather than only against a test-seeded
row.

Purpose: 07-01 proved the write path produces rows the Phase 4 alias read accepts. This plan adds
the two verbs that read the ledger back before writing to it, which is where the interesting
failure modes live: an unknown semver, a semver belonging to another alias, a tombstoned target, and
a retirement that would strand the alias.

Output: `Databasise.rollback()`, `Databasise.retire()`, three refusals, two test modules.
</objective>

  <action>
Add `async def rollback(self, alias, version, trace_ids, change_origin)` to `Databasise`, beside `promote()`. `version` is a required positional parameter with no default — D-05 settles that rollback names an explicit semver target and there is no default "previous". A default would let an operator repoint an alias to a generation they never named, which is a promotion decision made by the machine on their behalf.

Reuse `promote()`'s validation prologue verbatim rather than copying it: refuse an invalid `change_origin`, refuse an empty `trace_ids`, resolve every trace id through `self._trace_store`, and call `promotion.resolve_single_arm`. Extract that prologue into one shared private helper on `Databasise` (or one function in `promotion.py` taking the already-resolved trace records) so there is exactly one place where the operator-path preconditions live — three copies is where one of them quietly stops being checked.

Then resolve the target generation: `Ledger(self.store_root).generation_state(alias, version)`.

- `None` → `UnknownGenerationVersionError(alias=alias, version=version)`. This one refusal covers both "this alias never minted that version" and "that version was minted under a different alias", because from the caller's own vocabulary those are the same fact: *this alias has no such generation*. Naming the other alias would disclose a generation the caller did not ask about.
- `record_kind == RECORD_KIND_TOMBSTONE` → `TombstonedGenerationError(alias=alias, version=version)`. RIG §PR.2 and CONTRACT §0.4: a retired generation is not reachable again.

Note carefully what `generation_state` does and does not check. It returns the **latest** record naming that `(alias, version)` generation — never "does a tombstone exist anywhere in this mutation's history". Scanning history would make a wiring that was retired once and legitimately re-promoted later permanently unpromotable, because the re-promotion is a different generation with a different version and has nothing to do with the retired one.

Construct the record. `mutation_id` = the target generation record's own `mutation_id` — the wiring being returned to, read from the ledger, never named by the caller. `parent` = that same mutation id, which is RIG §PR.2's own instruction that the record name what it returns to. `targets_version` = the caller's `version`. `record_kind = RECORD_KIND_ROLLBACK`. `promotion_provenance = PROVENANCE_OPERATOR_ASSERTED`, `promotion_trace_ids` = the caller's list, `proposer_id = "operator"`, `change_origin` = the caller's value, `alias` = the caller's alias. `verdict`, `tier_of_decision`, `evidence_pointer`, `effect_size`, `depth_label` and `decomposition_ratio` all `None` — this record carries no new arm run and no verdict, exactly as RIG §PR.3 states for the operator path. `arm_instance_hashes` = the distinct wiring instance hashes off the resolved trace records, as `promote()` already does.

`minted_version` is a **newly minted** semver, not the target's. CONTRACT §0.4 says a published name is never reused; re-publishing `1.0.0` for a second, later generation would make two distinct ledger rows claim the same public handle and would break the `(alias, version)` keying `generation_state` depends on. Mint it with the same `promotion.mint_version` call promote uses: prior version = the alias's current active generation's `minted_version`, and the surface comparison is between the rolled-back-to wiring and that current active generation's wiring. Derive `mutation_class` the same way, from the same two wirings.

One `append()` in one transaction is the atomic repoint, exactly as in `promote()`. Offload it with `run_in_executor` at this async call site. Return the same `PromotionResult` model, with `record_kind` reporting `"rollback"`.

Add `UnknownGenerationVersionError(*, alias, version)` and `TombstonedGenerationError(*, alias, version)` to `refusals.py` in the established keyword-only style, each embedding its class name in the message and each added to `__all__`. Export `rollback` from `databasise/seam/__init__.py`.

  <action>
Add `async def retire(self, alias, version, trace_ids, change_origin)` to `Databasise`, with the same parameter shape as `rollback` so the three verbs read as one family across all three transports. Reuse the shared precondition helper Task 1 extracted — this verb applies the identical `change_origin`, non-empty-trace-ids, resolvable-and-agreeing checks.

**A deliberate, stated non-requirement:** the resolved arm does **not** have to match the generation being retired. RESEARCH.md's Open Question 2 left this unsettled and CONTEXT.md D-07 does not decide it; the reading this plan adopts is that an operator's judgment that a generation should stop being eligible may legitimately be formed by reading traces of a different run that demonstrated the problem. The trace ids are still required, still must resolve, and still must agree on one arm — so the refusal vocabulary stays uniform across all three verbs — but the resolved arm is recorded, not matched. State this in `retire()`'s own docstring so a later reader does not "fix" it into a match check.

Resolve the target generation through `Ledger.generation_state(alias, version)`:

- `None` → `UnknownGenerationVersionError(alias=alias, version=version)`, the same refusal `rollback` raises.
- `record_kind == RECORD_KIND_TOMBSTONE` → `TombstonedGenerationError(alias=alias, version=version)`. Retiring an already-retired generation is refused rather than silently appending a second tombstone: a no-op that reports success is indistinguishable from a real retirement to the caller.

Then the active-generation guard. Read `Ledger.by_alias(alias)`; if its `minted_version` equals the caller's `version`, raise `ActiveGenerationRetirementError(alias=alias, version=version)` with a message stating the operator must roll back first. The reason, recorded here because it is this plan's own discretionary call: retiring the generation an alias currently derives from would leave the alias resolving to a wiring that has just been declared ineligible, and CONTRACT §16.2 already refuses pins to tombstoned artifacts. The alternative — having `by_alias` walk backwards to the most recent non-retired generation — would be a second alias-lifecycle mechanism, and CONTEXT.md states plainly that alias lifecycle beyond "first promotion creates the alias" is "not required and not asked for". Refusing is the smaller, more honest surface, and it composes: roll back, then retire.

Construct the tombstone record. `mutation_id` = the target generation record's own `mutation_id`, read from the ledger. `targets_version` = the caller's `version`. `minted_version = None` — a retirement mints nothing, and this is exactly why 07-01 gave the minted and targeted versions separate columns instead of overloading one. `record_kind = RECORD_KIND_TOMBSTONE`. `parent = None`. `promotion_provenance = PROVENANCE_OPERATOR_ASSERTED`, `promotion_trace_ids` = the caller's list, `proposer_id = "operator"`, `change_origin` = the caller's value, `alias` = the caller's alias, `mutation_class` = derived the same way the other two verbs derive it, so a retirement is classed rather than carrying a placeholder. `verdict`, `tier_of_decision`, `evidence_pointer`, `effect_size`, `depth_label`, `decomposition_ratio` all `None`.

One `append()`, offloaded with `run_in_executor`, and no second write. Return `PromotionResult` with `record_kind` reporting `"tombstone"` and `version` reporting the retired version — the field's meaning is disambiguated by `record_kind`, and that is stated in the model's own docstring rather than left for a reader to infer.

**Nothing lifts a tombstone, and the implementation must make that structural rather than defensive.** There is no un-retire verb, no flag on promote that revives a generation, and no code path that updates or deletes a tombstone row — the database triggers refuse both anyway. Re-promoting the same wiring later is a new generation with a new minted version (D-07), which the ledger expresses naturally because versions are never reused: the retired `(alias, version)` pair keeps reporting a tombstone through `generation_state` forever, while the new generation is a different pair. Do **not** add a promote-side check that refuses an arm whose earlier generation was retired — that would contradict D-07's own last sentence and would make a legitimately re-promoted wiring permanently unpromotable.

Add `ActiveGenerationRetirementError(*, alias, version)` to `refusals.py` in the established style and to `__all__`. Export `retire` from `databasise/seam/__init__.py`.

Write `databasise/tests/seam/test_retire.py` covering the `<behavior>` block. `test_never_lifted_repromotion_is_a_new_generation` is the load-bearing one — it is what makes SC1's "tombstoned losers are never lifted" true against the real write path rather than only against a hand-seeded row, which is all the existing suite could show before this phase.
