Querying a never-populated LightRAG vector namespace is refused by name before any model call, and reading a namespace creates nothing (LRAG-16, D-15). Query traces carry no no-op `embedder-index` node: the node stays in the wiring as the index recipe and is skipped at query time (LRAG-19, D-04 as resolved by research Q4).

Purpose: ROADMAP criterion 5 ("an unpopulated namespace is distinguishable from no match"; "query traces carry no no-op embedder-index node").
Output: lazy directory creation in the Faiss store, the named refusal and its pre-check, the recipe-only skip, and tests.

Q4 binds: `embedder-index` is not removed from any wiring or arm patch, so `derive_mutation_class`, the promotion tests and RUN-11's reproduction test keep their inputs. "Marked recipe-only" means the node is named as a value of the wiring's `recipe` map and no other node depends on it. The engine drops such nodes from the copy it parses and runs for a query. Every identity it derives (instance hash, wiring id) still comes from the full resolved wiring.
</objective>
