<objective>
A query that runs nodes and then refuses leaves a resolvable trace: the engine persists the RunRecord before any post-dispatch refusal and hands the refusal a public `trace_token`, and two answering provides nodes become a named refusal instead of a 500 (WIRE-12, D-04). Consumer reason fields are checked at response time against the closed code set, so an old stored text or a regression can never show a node id (WIRE-03, D-05, D-23).

Purpose: ROADMAP Phase 13 criterion 3 (runs that raise after executing nodes still persist a resolvable trace) and criterion 2 (node detail only under debug; the leak check runs before responses are returned).
Output: persist-before-raise restructure, one new refusal, the response-time check in `seam/redact.py`, test updates.
</objective>
