Facts this plan relies on:
- Stream wire format: blocks of `data: {"kind": "evidence", "evidence": {...}}` and then `data: {"kind": "final", ...envelope minus evidence}`, separated by blank lines, with no `event:` line. The content type is `text/event-stream; charset=utf-8`. A refusal arrives as a plain JSON 4xx before any byte. Rebuild the envelope as `Object.assign({}, final, {evidence: collected})` without `kind`.
- Real error shapes on POST /query (probed this session):
  - selector `{"alias": "a", "capability": ["reads_kv"]}` gives 422 `MultiMemberSelectorError`, a typed refusal;
  - an unknown alias gives 422 `UnsatisfiableSelectorError`;
  - selector `5` gives a validation 422 with `loc ["body", "selector"]`;
  - text `["a"]` gives a validation 422 with `loc ["body", "query", "text"]`.
  The inputs carry `data-field-loc="body.selector"` (parts/selector.html) and `data-field-loc="body.query.text"` (query.html).
- `LiveApp.fail("query")` makes the server answer a real 500; `start_live_app(..., log_file=path)` mounts GET /log.
- Playwright `route.fetch()` plus `route.fulfill(response=resp, body=...)` truncates or prefixes a real stream. `route.continue_(post_data=...)` rewrites a request so that the real server answers it.
- Query mode ids: `query.run.submit`, `query.run.stream`, `query.run.message`, `query.state.*`, `query.result.*` (answer, trace-link, promote, compare), `query.evidence.table`, `query.evidence.open-1..5`, `query.history.table`, `query.history.open-1..3`, `query.error.*`.
