Facts this plan relies on:
- POST /promote, /rollback and /retire take `{alias, trace_ids[], change_origin, verb?}`; rollback and retire add `version`. They return `{alias, version, record_kind, provenance, generation_ordinal}`. `change_origin` is `human_edit` or `machine_mutation`.
- POST /ledger/history `{alias, limit, offset}` returns `{records[{generation_ordinal, created_at, record_kind, minted_version, targets_version, change_origin, promotion_trace_ids, active, tombstoned}], total, next_offset}`, ascending. Limit 0 gives `PageBoundsError`, and 101 gives `PageSizeExceededError`.
- Server semantics on promote(v1), promote(v2), rollback to v1 (v3), retire(v2): `active` is true for the v1 promotion and the rollback record; `tombstoned` is true for the retired v2 promotion and for the tombstone record (test_console_ledger.py:126-131).
- POST /promote/preview returns `{arm, mutation_class, next_version, promotable, reason}`. GET /traces returns `{items[{trace_reference, created_at, partial, degraded, stop_reason}], total, next_offset}`, newest first.
- Ids: `ledger.aliases.*`, `ledger.promote.*` (alias with `data-field-loc="body.alias"`, source-history, source-recent, traces, trace-N, origin-human, origin-machine, preview, preview-result, submit, result), `ledger.timeline.*` (alias, notice, table, rollback-N, retire-N, prev, next, page-size), `ledger.error.roll-back-first`, and the dialogs `shell.dialog.promote*`, `shell.dialog.rollback*`, `shell.dialog.retire*`.
- Engine methods behind the routes: `POST /promote` calls `engine.promote`, `POST /rollback` calls `engine.rollback` and `POST /retire` calls `engine.retire` (rest.py:533-543); `POST /promote/preview` calls `engine.preview_promotion`, `POST /ledger/history` calls `engine.ledger_history`, `GET /ledger/aliases` calls `engine.ledger_aliases` and `GET /traces` calls `engine.list_traces` (operator_rest.py:90-115). `LiveApp.hold` and `LiveApp.fail` take these names.
