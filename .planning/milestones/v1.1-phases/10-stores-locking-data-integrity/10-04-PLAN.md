<objective>
Expansion plan (STOR-06, first half). An ingest whose run records any node failure, or that stopped early, commits nothing: the engine drops every store's pending writes and raises `ForeignEngineRefusalError` (D-06). A store error inside a node surfaces as `failure_class="StoreFault"` (D-13), and an early stop with no exception as `"RunIncomplete"` (Q2). The one node-level flush in a shipped part is removed, so the engine owns the commit (D-09).

Purpose: ROADMAP criterion 3 ("a failed ingest ... commits nothing"). 10-05 replaces the success-path flush with prepare-all/commit-all.
Output: the extended `_node_result_or_refuse`, `_drop_pending`, `_is_store_fault`, the reworked ingest flow, the D-13 wording, the removed node-level flush, and `tests/seam/test_ingest_abort.py`.
</objective>

- `seam/engine.py` ingest: after `run_wiring` it flushes every store unconditionally (the `for store in stores.values(): await store.index_done_callback()` loop, about 862-872). Only after the `finally` that finalizes the stores does it call `_node_result_or_refuse(scheduled, result_node_id, "ingest")` (about 886-891). So a failed HippoRAG run has already committed the chunk-embed and entity-fact-embed writes (the STOR-06 defect).
- `_node_result_or_refuse` (`engine.py:430-458`) checks only the given node's exception and result. `run_wiring` returns `results`, `node_exceptions`, `partial`, `stop_reason`, `nodes`, `degraded`, `degradation_reason`, or `cycle` for a cyclic wiring. `delete_document` also calls the helper, so the new rules apply to it (10-10 adds its flush and drop).
- `_foreign_fault(operation, cause, *, failure_class=None)` (`engine.py:248-258`) logs once and builds the refusal. `ForeignEngineRefusalError` (`refusals.py:745-771`) classifies by the cause's type name through `_FOREIGN_FAILURE_CLASSES`, defaulting to `UnclassifiedEngineFailure`; an explicit `failure_class` wins. `rest._status_for` returns 503 only for `_ENGINE_UNAVAILABLE`, otherwise 502. `rest._FAULT_RESPONSES[502]` says "the v1 engine run failed".

It is the only lifecycle call in any part (research Pitfall 5). `parity/build_hipporag_index.py:273-274` flushes the graph itself, so removing the node-level call does not lose its writes.
