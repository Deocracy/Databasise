- `HealthReport` (`seam/corpus.py:285-301`) is frozen with `extra="forbid"`; `stores: dict[str, bool]`. REST `get_health` returns it (`rest.py:466-468`), and MCP returns `engine.health()` (`mcp/server.py:144-146`), so both follow the model. `docs/system-model/CONTRACT.md` §18 does not define `HealthReport` (research), so CONTRACT is not amended.

The protected `tests/seam/test_rest_corpus_endpoints.py:256-259` compares REST JSON to `model_dump()` and is shape-agnostic, so it needs no edit.
- Measured while planning (scratchpad `walprobe.py`, `walprobe2.py`): on a WAL `kv.sqlite3` with no open writer, `sqlite3.connect(uri + "?mode=ro", uri=True)` leaves `kv.sqlite3-wal` and `kv.sqlite3-shm` behind. With `?mode=ro&immutable=1` it creates nothing. When a writer is open, the `-wal` file already exists and `?mode=ro` reads committed rows without blocking. A garbage file raises `sqlite3.DatabaseError`. Use `Path.as_uri()` to build the URI.
- Measured while planning (scratchpad `cozoprobe.py`): opening an existing `graph.cozo` rotates RocksDB's own files inside `graph.cozo/data/` (new `.log`, `MANIFEST`, `OPTIONS`, `LOG.old`). Nothing is created outside `data/`, and no relation is added. Opening a missing path creates it (S1), so the probe checks `graph.cozo` exists first. `client.run("::relations", {}, True)` is the immutable read (S2).
- Vector namespaces live only in part constants: `parts_core/lightrag/{chunk_vector,entity_lookup,relation_lookup}.py` and `parts_core/hipporag/{chunk_embed,entity_fact_embed,fact_score}.py` (research Pattern 6, Pitfall 19).
- `load_committed` (10-06) returns `None` for an absent pair and raises `VectorStoreCorruptedError` for a mismatched or half-written one. `_ClientRegistry.acquire/release` and `GraphStoreBusyError` are in `stores/graph.py` (10-01). `hold_graph_in_subprocess` is in `databasise.tests.stores.test_graph_lock`.
- The `TraceStore` creates `store_root/trace.db` when the engine is constructed, so take the "before" listing after construction.
