# Lane 9 findings: Output composition for a frontier consumer

22 screened, 22 admitted, 0 refuted, 0 abstained. PDFs for all 22 in `papers/`.

## (a) Admitted items

**LLMLingua (2310.05736).** A small LM (GPT-2-small/LLaMA-7B) compresses prompts coarse-to-fine: a budget controller allocates compression ratios across prompt components, an iterative token-level pass models dependencies between kept tokens, and an instruction-tuning step aligns the small compressor's distribution with the black-box consumer; up to 20x compression with ~1.5 points of loss on GSM8K/BBH/ShareGPT/Arxiv (EMNLP 2023, code at https://github.com/microsoft/LLMLingua). MelodyScribe should take the budget-controller idea (different payload zones deserve different compression ratios) and the alignment step (a compressor tuned against the consumer's distribution beats a generic one). Careful: compression is question-agnostic here, so on retrieval payloads it keeps noise — LongLLMLingua shows this fails exactly where density matters.

**LongLLMLingua (2310.06839).** Question-aware extension of LLMLingua: document score from question perplexity conditioned on the document plus a restrictive statement, token-level contrastive perplexity (shown equivalent to conditional PMI), document reordering against position bias, dynamic compression ratios, and subsequence recovery; NQ up +21.4% with ~4x fewer tokens into GPT-3.5-Turbo (ACL 2024). MelodyScribe should take contrastive perplexity as the cheapest query-aware salience signal for ranking/ordering payload spans, and the reordering mechanism as mandatory given Lost-in-the-Middle. Careful: the authors state question-aware compression prevents caching and roughly doubles compression compute — a per-section precomputed payload plus a cheap query-side rerank may beat per-query recompression.

**LLMLingua-2 (2403.12968).** Distils GPT-4 compression behaviour into a small encoder (XLM-R-large/mBERT) framed as token-level preserve/discard classification, trained on a MeetingBank-derived extractive dataset with quality-control filtering; task-agnostic, 3–6x faster than perplexity methods, 2–5x end-to-end compression (Findings of ACL 2024, dataset released). MelodyScribe should take the dataset recipe — teacher generates compressions under a strict delete-only instruction, annotation aligns them to token labels, QC filters the failures — as the template for building its own payload-composition training data. Careful: delete-only extractive compression preserves faithfulness but cannot synthesize, reorder, or write Folios; it covers half the composer job.

**RECOMP (2310.04408).** Two small compressors trained against the frozen consumer's end-task signal: an extractive one via contrastive learning on sentences that lead to correct outputs, and an abstractive one distilled from GPT-3 with candidates filtered by downstream LM performance rather than ROUGE; both implement selective augmentation (emit empty string when retrieval is useless), reaching ~6% oracle compression and 5–10% token budgets on QA at <10% relative drop, transferring across consumer LMs (ICLR 2024, code https://github.com/carriex/recomp, compressors on Hugging Face). MelodyScribe should take end-task filtering (keep the candidate payload that makes the consumer right, not the one that looks like a good summary) and selective augmentation (sections with no query-relevant content should contribute nothing). Careful: their abstractive compressor is a separate encoder-decoder, not the embedder's own weights, so it says nothing about joint training interference.

**FILCO (2311.08377).** Sentence-level filtering: silver labels from three utility measures (string inclusion, lexical overlap, conditional cross-mutual information — the probability lift the context gives the generator), then a trained filter model plus a generator fine-tuned on filtered context; +2.8/3.0 points average over six tasks with 44–64% shorter prompts, with different tasks preferring different measures. MelodyScribe should take CXMI-style utility labels as the supervision signal for Proof-adjacent evidence selection (keep the sentence that raises the consumer's probability of the right answer), and the finding that the best filter varies by task (route or multitask the filter). Careful: silver labels need gold answers at train time, so this shapes the dataset build, not inference.

**Selective Context (2310.06201).** Self-information from a base causal LM filters tokens/phrases/sentences by percentile; 50% context reduction at −0.023 BERTScore, but usable thresholds differ by domain (arXiv breaks past 0.35–0.5 reduction, news tolerates more). MelodyScribe should take only the negative lesson plus the percentile mechanism: content-agnostic entropy filtering is the baseline to beat, and any fixed reduction ratio must be calibrated per corpus. Careful: LongLLMLingua shows this class of method underperforms zero-shot on noisy retrieval prompts — do not ship it as the composer.

**Gist tokens (2304.08467).** An attention-mask modification during instruction tuning forces the model to route prompt information through a few learned gist tokens, achieving up to 26x compression with ~40% FLOPs reduction at no extra training cost; framed as meta-distillation of the instruction-tuned LM (NeurIPS 2023, checkpoints released). MelodyScribe should take this as the closest existence proof for its core bet: one set of weights can simultaneously learn to follow instructions and to compress content into a hidden-state bottleneck, with compression learned jointly rather than bolted on. Careful: gists compress instructions for reuse, not documents per query, and they are opaque activations — unverifiable by Proof and non-portable to a frontier consumer, so this supports the [EMB]-marker mechanism but not the payload format.

**AutoCompressors (2305.14788).** Pre-trained LMs adapted with summary tokens and summary accumulation on an unsupervised segmented-LM objective compress long documents into soft summary vectors; OPT-2.7B and LLaMA-2-7B trained on sequences up to 30,720 tokens on a single 80GB GPU, beating comparable-token plain-text ICL on 8/11 tasks with caching and reuse (EMNLP 2023, models released). MelodyScribe should take the single-GPU feasibility proof and summary accumulation (per-section compression that composes across a document) as the architectural sketch for per-section [EMB] states. Careful: the authors note fine-tuning domain mismatch degraded zero-shot/ICL behaviour — the same forgetting risk spike 011 is testing — and soft vectors are consumer-locked.

**ICAE (2307.06945).** A LoRA-adapted encoder (~1% added parameters, rank 128) compresses context into memory slots consumed in-context by the frozen LLM itself; pretraining mixes autoencoding and LM objectives (best λ 0.4–0.6) before fine-tuning on 240k prompt-with-context triples; 4x compression on LLaMA with 2–3.5x inference speedups (ICLR 2024, PWC dataset and model released). MelodyScribe should take the split — cheap trainable encoder, frozen consumer — and the two-stage curriculum (reconstruction first, instruction-conditioned use second) as the safest joint-training starting point, plus the PWC dataset as a format template. Careful: 4x is modest next to hard-compression ratios, and slots are still consumer-specific vectors, not frontier-readable text.

**xRAG (2405.13792).** Reframes a frozen dense retriever's document embedding as a retrieval modality: a two-layer projector (<0.5% of parameters) maps it to a single token for a frozen LLM, trained with paraphrase pretraining then context-aware instruction tuning; +10% average over six knowledge tasks at 3.53x fewer FLOPs (NeurIPS 2024). MelodyScribe should take the headline result — a retrieval embedding already contains nearly as much usable content as the text — as the strongest external support for emitting embeddings and generations from one forward pass. Careful: single-document only (multi-document listed as future work), the projector is consumer-specific so the token is not portable to a different frontier model, and interpretability/verbatim-evidence requirements rule out pure soft payloads for Proof.

**Lost in the Middle (2307.03172).** Controlled position sweeps show U-shaped consumer accuracy (best at context start/end, worst in the middle, sometimes below closed-book) and reader QA saturating by ~20 retrieved documents while retriever recall keeps climbing; prescribes reranking relevant content to the edges and truncating (TACL 2024). MelodyScribe should take this as the governing constraint on payload assembly: ordering and truncation dominate payload volume, so the composer must rank, place the best evidence first/last, and stop adding documents past saturation. Careful: results are consumer- and task-specific (query-aware contextualization helped key-value lookup but barely moved multi-doc QA), so re-measure saturation on the parity corpus with the actual frontier consumer.

**Voyager (2305.16291).** An LLM agent accumulates an ever-growing library of model-written executable code skills, indexed by description embedding with top-5 retrieval and composed into harder skills, admitted only after execution feedback and self-verification; 3.3x more items and 15.3x faster milestones than prior agents. MelodyScribe should take the Folio blueprint: model-written procedures, embedding-indexed, compositional, gated by a verifier before library admission. Careful: Voyager's verification is environment execution, not a grammar/quote checker, and nothing measures a downstream consumer's gain from the library — the Folio-utility experiment is still unrun.

**MemGPT (2310.08560).** OS-inspired virtual context management: a fixed-context LLM pages information between main context and archival/recall stores via function calls, with heartbeat chaining for multi-step retrieval; demonstrated on over-length document analysis and multi-session chat (code continued at https://github.com/letta-ai/letta). MelodyScribe should take the paging discipline (explicit read/write/evict decisions over a bounded working payload) as the runtime pattern for assembling payloads larger than any single budget. Careful: it is a prompting architecture, not a trained composer — no weights, no training recipe, no consumer-quality measurements.

**RAPTOR (2401.18059).** Recursive embed–cluster–summarize builds a tree of abstraction levels over a corpus at linear build cost; collapsed-tree retrieval (all levels competing) beats layer-by-layer traversal, and GPT-4 over RAPTOR trees gains +20pp absolute on QuALITY (ICLR 2024, code https://github.com/parthsarthi03/raptor). MelodyScribe should take collapsed multi-level retrieval as the payload-assembly pattern for sectioned documents (leaf quotes plus parent summaries in one payload) and the linear-cost clustering build as the indexing analogue. Careful: tree construction burns teacher/consumer summarization calls per node, andoptimal level-mix is query-dependent — the composer must learn the mix, not fix it.

**Self-RAG (2310.11511).** A single LM learns reflection tokens (retrieve? relevant? supported? useful?) inserted offline by a critic model distilled from GPT-4, then trained with the standard LM objective; the 7B/13B generators beat ChatGPT and retrieval-augmented LLaMA-2-chat on open QA, reasoning, and fact verification, with controllable adaptive retrieval at inference (ICLR 2024, models at https://github.com/AkariAsai/self-rag). MelodyScribe should take the training pattern — offline critic labels control tokens, generator learns them as ordinary next tokens — as the template for learning Proof-shaped gates (emit/retrieve/abstain) inside the small model. Careful: reflection tokens are model-internal control signals, not consumer-visible evidence; Proof still needs verbatim quotes alongside any learned gate.

**QMSum (2104.05938).** 1,808 query-summary pairs over 232 multi-domain meetings with relevant-span annotations; the locate-then-summarize baseline and the finding that single-domain training fails cross-domain (NAACL 2021, data https://github.com/Yale-LILY/QMSum). MelodyScribe should take the annotation schema (query, relevant spans, summary) as the minimum viable format for its own payload-composition dataset, and the cross-domain failure as a warning to cover document variety early. Careful: meeting transcripts are far from the parity corpus's documents, and QMSum measures summary quality, never downstream consumer gain.

**GSM-IC (2302.00093).** Adds irrelevant sentences to math problems and shows all prompting techniques collapse (≤18% of solvable problems stay solved across distractor types); self-consistency, distractor-bearing exemplars, and explicit ignore-instructions partially recover (ICML 2023). MelodyScribe should take the measurement frame — consumer accuracy as a function of payload noise — and the mitigation main effect: training/evaluating with distractors present beats training clean. Careful: arithmetic reasoning with synthetic distractors is not retrieval payloads; the transferrable claim is methodological, not numeric.

**Robust RALM (2310.01558).** Five-benchmark analysis of when retrieval hurts (including multi-hop cascades); an NLI entailment back-off baseline plus a 1,000-example fine-tune on mixed relevant/irrelevant contexts makes the reader robust while keeping relevant-context gains (Yoran et al., preprint). MelodyScribe should take the 1,000-example mixed-context fine-tune as the cheapest dataset arm for spike 011: relevant, irrelevant, and partially-relevant sections for the same query, with the target payload/answer unchanged when the context is noise. Careful: fine-tunes the reader, not a composer, and multi-hop robustness came from training through the retriever's actual noise distribution — synthetic noise must match deployment noise.

**ARES (2311.09476).** Synthetic in-domain QA generation plus fine-tuned lightweight judges for context relevance, answer faithfulness, and answer relevance, calibrated with prediction-powered inference from ~150–300 human labels; beats RAGAS by ~59pp/14pp on relevance judgments and resolves near-tied systems (NAACL 2024, code https://github.com/stanford-futuredata/ARES). MelodyScribe should take the three-metric split as its payload→consumer eval protocol (is the payload relevant? is the answer grounded in it? does it answer the query?) and PPI as the way to keep human labelling affordable on a private corpus. Careful: judges are domain-fitted classifiers needing their own synthetic data pipeline per corpus, and judge-only optimization without held-out human checks is a known failure mode.

**Generative Agents (2304.03442).** Memory stream scored by relevance, recency, and importance, with reflection synthesizing higher-level inferences that are stored back and retrieved for planning; ablations show each component matters, and the failure taxonomy (retrieval misses, memory confabulation, inherited formality) is directly reusable (UIST 2023, code https://github.com/joonspk-research/generative_agents). MelodyScribe should take the tripartite retrieval score as the ranking function for payload assembly and the reflection loop as the Folio-writing pattern (observations → synthesized procedure → stored, re-retrieved). Careful: believability judgments, not task or consumer-QA metrics, so the link from reflection quality to answer quality is unmeasured.

**RankGPT (2304.09542).** Instructional permutation generation with a sliding window lets frontier LLMs rank passages directly; GPT-4 beats supervised rankers, and distilling ChatGPT permutations via RankNet into a 435M student beats a 3B monoT5 on BEIR (+1.67 nDCG) (EMNLP 2023 Outstanding Paper, code https://github.com/sunnweiwei/RankGPT). MelodyScribe should take permutation distillation as the concrete mechanism for teaching the small model to order payload content: teacher ranks, student learns scores, consumer reads the ordered payload. Careful: optimized for ranking metrics, not for downstream answer quality, and the sliding-window trick is an inference workaround, not a training principle.

**Reflexion (2303.11366).** Actor/evaluator/self-reflection loop converting scalar or language feedback into verbal critiques kept in a small (1–3) episodic buffer; 91% HumanEval without weight updates (NeurIPS 2023, code https://github.com/noahshinn/reflexion). MelodyScribe should take the episodic verbal-feedback buffer as the inference-time complement to training: Proof failures become critiques attached to the section for the next attempt. Careful: gains are prompting-level and trial-bounded; nothing here trains weights, so it bounds what a no-training Folio loop can achieve.

## (b) Refutations

No admitted primary source contradicts a claim stated in the brief. Two tensions against natural assumptions are recorded as cautions, not refutations: (i) a naive "more payload helps" assumption is contradicted by Lost-in-the-Middle (mid-context performance can fall below closed-book, 2307.03172) and by Robust-RALM (retrieval hurts accuracy on 2/5 benchmarks, 2310.01558) — neither contradicts the brief, which makes no such claim; (ii) LongLLMLingua's question-aware requirement sits in apparent tension with spike 007's prompt-insensitivity finding, but the objects differ (compression salience vs embedding similarity), so this is a non-contradiction pending a joint measurement.

## (c) Unresolved ledger

1. No public work measures a frontier consumer's answer quality as a function of payloads built by a ≤3B grammar-constrained composer; closest are RECOMP's end-task filtering with a GPT-3 teacher and RankGPT's distillation evaluated on ranking metrics. Reason: gap, not miss — searched compression, RAG-eval, and reranking venues.
2. No evaluation of model-written procedural skills (Folios) by downstream consumer gain; Voyager and Generative Agents measure task success and believability. Reason: gap.
3. Cross-consumer portability of soft payloads (gist/ICAE/xRAG/AutoCompressor vectors) at small scale is unmeasured; xRAG's projector is consumer-specific by construction. Reason: gap with a negative prior.
4. The faithfulness-vs-utility tradeoff for verbatim-quote-constrained payloads is unquantified; compression work optimizes one or the other. Reason: gap.
5. No query-focused dataset with evidence-span annotations exists for graph/SQL-op payloads at any scale; QMSum's schema transfers but its domain does not. Reason: gap.

## (d) Security findings (requirements)

- R1 — Provenance preservation: every payload span must carry its source section/document id through assembly (cf. ARES faithfulness, RAPTOR node identity), so Proof and auditors can trace claims to bytes.
- R2 — Untrusted-payload discipline: composed payloads are untrusted input to the frontier consumer; filtering (FILCO/CXMI class) and quote verification (Proof) must run before any payload reaches the consumer, given measured distractibility (GSM-IC, Robust-RALM) and position sensitivity (Lost-in-the-Middle).
- R3 — Folio admission control: model-written Folios must pass self-verification plus Proof before entering any reusable library (Voyager's commit gate), and library retrieval must be scoped per query to avoid stale-procedure reuse.
- R4 — Judge hygiene: any LLM-judge scoring payloads or answers requires held-out human labels with confidence intervals (ARES/PPI pattern); never optimize the composer against an uncalibrated judge alone.
