## 1. Verdict — does anything already do this?

**No.** Four capabilities define this project: (a) an **agnostic fitting** that hosts non-overlapping modality types, (b) **versioned components** (`name@version`, immutable, lineage-tracked), (c) **parallel comparison** of N wirings on one corpus, (d) **self-improvement** (the system mutates its own components and adopts winners). Each capability has solid prior art. **No surveyed system holds more than two, and only one system holds two.**

| System | (a) agnostic fitting | (b) versioned components | (c) parallel comparison | (d) self-improvement |
|---|---|---|---|---|
| **AutoRAG (legacy)** | partial — name→callable registry, module identity is data [code-verified, PA1] | none — swap-the-latest only [code-verified, PA1] | **yes, trial-level** — module × param sweep to one `summary.csv` [code-verified, PA1] | partial — *selection* over a fixed catalogue, never mutation [code-verified, PA1] |
| **DSPy** | no — no declared graph at all; pipeline = Python call structure [inference, PA2] | partial — predictor *state* (`dump_state`), never wiring topology [docs-verified, PA2] | partial — `BootstrapFewShotWithRandomSearch` / `Ensemble` only, inside one compile [docs-verified, PA2] | **yes, shipped** — `compile()` = branch→mutate→score→keep [code-verified, PA2] |
| **Haystack 2.x** | **yes** — typed sockets, wiring-time validation, cycles, SuperComponents [code/docs-verified, PA2] | none — identity is `{"type": "<import path>", "init_parameters": {...}}`, no version field, no hash, no lineage [code-verified for format; inference for the absence, PA2] | none | none |
| LangGraph | partial — untyped `State→Partial<State>` nodes, no wiring-time validation [docs-verified, PA2] | no — *state channel* versions are per-run bookkeeping, not artifact identity [docs-verified, PA2] | none | none |
| LlamaIndex Workflows | partial — typed events, but topology exists only as scattered source [docs-verified, PA2] | none found — explicit absence [docs-verified, PA2] | none | none |

| RAGFlow | partial — enforced `ComponentBase`, named ports, control flow as node types [code-verified, PA1] | none | none | none |
| Cognita / Verba / Canopy / fastRAG | partial (Verba's `InputConfig` manifest is the strongest) [code/docs-verified, PA1] | none | none | none |
| MLflow / HF Hub / DVC / Nix / lakeFS / Pachyderm / Feast | n/a — not RAG | **yes** — immutable versions + lineage + promote, four independent designs [docs-verified, PA3] | n/a | n/a |
| GrowthBook / Statsig | n/a | n/a | **yes** — assign → expose → analyze → promote as first-class objects [docs-verified, PA3] | no — selects among variants, never authors them |

### The closest three, and the exact gap

**1. AutoRAG (legacy Python tree, `legacy-v0.3.24`) — closest overall to the improvement loop.**
What it already has: module identity as data (`Module` dataclass, `module_type: str` resolved via `get_support_modules`) [code-verified, PA1]; Cartesian sweep over module × hyperparameter lists from YAML [code-verified, PA1]; composite multi-metric winner selection with a hard threshold pre-filter [code-verified, PA1]; and the three-artifact promotion split — trial log (`summary.csv`) → `extract_best_config()` emits a clean single-module-per-node YAML → a separate `Runner` executes only pinned configs [code-verified, PA1].
**The gap, precisely:** (i) no version axis at all — a "module" is whatever the installed code currently is, so a trial run is not reproducible next month and rollback is not re-pinning; (ii) search is **greedy node-by-node**, explicitly to dodge combinatorial blow-up [docs-verified, PA1], so cross-stage interaction effects are foreclosed by construction; (iii) losing trials die at `extract_best_config` — there is no standing A/B between two independently-authored wirings after the fact [code-verified, PA1]; (iv) `node_line`s are linear — no loops, no branches, so four of six agentic control-flow shapes are unrepresentable [SYNTHESIS.md §4, code-verified]; (v) improvement is **selection over a fixed catalogue**, never proposal of a new component. It searches; it does not evolve.
**Governance gap (non-technical, decisive):** the repo has been **repurposed** — `main`, the description, and `v2.0.0`/`v2.1.0` are now a TypeScript coding-agent tool; the RAG optimizer survives only under `legacy/` [code-verified, PA1].

**2. DSPy — closest on the mutation mechanics, and the only shipped instance of (d).**
What it already has: `compile()` as a working branch→mutate→score→keep loop; `BootstrapFewShot` extracts passing traces into few-shot demos and reattaches them to the student's structurally-matched predictor [code-verified, PA2]; MIPROv2 rewrites instructions; **GEPA** does reflective prompt evolution and keeps a **Pareto frontier** of non-dominated candidates rather than one running-best [docs-verified, PA2]; `BootstrapFinetune` crosses from prompt-space into weight-space [docs-verified, PA2].
**The gap, precisely:** there is **no declared graph** — the "pipeline" is Python call structure, invisible to any external tool and unversioned as a topology; only predictor *state* is saved, never the wiring between predictors [docs-verified, PA2]. It therefore cannot express a modality as a mutable, diffable, A/B-able artifact — the exact thing rubric goal 7 makes load-bearing. It also has no storage/modality agnosticism (no fitting, no index recipes, no artifact sharing) and no notion of running two programs side-by-side on one corpus outside a compile. **DSPy proves the mutation mechanics work; it does not prove they compose with a declared-graph representation — no surveyed system does both** [PA2 §5].

**3. Haystack 2.x — closest on the fitting and executor.**
What it already has: `@component` + `run(**kwargs) -> dict` + `@component.output_types(...)`; `_types_are_compatible()` validating connections at **wiring time** with a `PipelineConnectError` naming the offending sockets [code-verified, PA2]; cycles as plain edges with a `max_runs_per_component` backstop; `warm_up()` keeping model loading out of `__init__` and the hot path; `SuperComponent` wrapping a sub-pipeline behind one component's signature [docs-verified, PA2].
**The gap, precisely:** node identity in the serialized spec is a **Python import path plus constructor kwargs** — no version field, no content hash, no lineage pointer [code-verified for the format, inference for the absence, PA2]. Reproducibility depends entirely on the installed package matching the YAML author's environment; two saved pipelines give no way to tell whether "the same" component changed between them. It has zero comparison machinery, zero mutation machinery, and its own observability story is "bolt on OpenTelemetry" [docs-verified, PA2], not `name@version`-tagged traces (rubric goal 9). This is precisely the design goal 7 forbids.

### The honest shape of the answer

The **union** of prior art covers all four capabilities. The **intersection is empty**, and the versioning axis's best prior art is not a RAG system at all — it is Nix, DVC, Pachyderm and Hugging Face Hub [docs-verified, PA3]. That is not a discouraging finding: it means this project's novel work is confined to **one seam** — making `name@version`-with-lineage the node identity inside a declared graph — and everything on either side of that seam is portable from something already shipped. It also predicts the build-vs-adopt answer in §4: the closest existing thing to what we want is not a system, it is a **stack** (Nix + git + DSPy + a Haystack-shaped executor + Cozo).

### What this survey adds to CANDIDATES.md (for the red team)

- **Candidate A's ceiling is now field-confirmed, not predicted.** LlamaIndex shipped the declared-DAG-of-components design (QueryPipeline) and **removed** it in v0.13.0, stating "the inability to perform loops in an AI application's logic is simply unacceptable" [docs-verified, PA2]. FlashRAG independently confirms it from the other direction: every control-flow-heavy method (Self-RAG, FLARE, IRCoT, RQ-RAG) had to be written as a one-off `BasicPipeline` subclass *outside* the stage taxonomy [code-verified, PA1].
- **Runtime-arity fan-out is unrepresented in all four candidate diagrams.** LangGraph's `Send()` (a router returns a *list* of `Send` objects, arity decided at runtime, merged by a per-state-key reducer) [docs-verified, PA2] has no analog in A/B/C/D.
- **Version-as-fixed-point vs version-as-search-space is an open question.** AutoRAG treats a component's *hyperparameters* as equally swappable, Cartesian-producting parameter lists into trials [code-verified, PA1]; our `name@version` model treats a version as one pinned configuration. Decide deliberately.
- **The mutable-pointer type is absent from every candidate.** All four diagrams show immutable `name@version` only; none shows the alias/champion pointer that patterns P12 and P15 require.

## 2. Design patterns to adopt (15)

| # | Pattern | Source | Strengthens |
|---|---|---|---|
| P1 | **Component identity is data all the way to instantiation** — a `Module` dataclass holds `module_type: str` + `module_param: Dict`, resolving to a callable via a central name→callable registry in `__post_init__`; `Module.from_dict()` builds one straight from YAML | AutoRAG `legacy/autorag/schema/module.py` [code-verified, PA1] — the strongest of five registry designs observed | Goals 3, 4; Candidates B, D. This is the substrate `name@version` extends: identity is already a string at the point of instantiation, so adding `@version` is a lookup-key change, not an architecture change |
| P2 | **Every component ships a self-describing schema of its own tunable parameters** — `config: dict[str, InputConfig]` where `InputConfig` carries `type`, `value`, `description`, `values` (allowed options), so a UI renders any component generically with no per-component frontend code | Verba `goldenverba/components/interfaces.py` [code-verified, PA1] | Goal 3 (the closest thing to a literal capability manifest in the survey) and Sourcerer's modality-agnostic seam — the GUI can configure a part it has never heard of |
| P3 | **Enforce the contract, don't document it** — base class raises `NotImplementedError` on every required method (`_invoke`, `thoughts`); keep expensive init out of `__init__` and off the hot path via a separate `warm_up()` | RAGFlow `agent/component/base.py` [code-verified, PA1]; `warm_up()` from Haystack [docs-verified, PA2] | Goal 2. Direct counter to failure mode F1. `warm_up()` matters specifically for a rig instantiating N wirings at once |
| P4 | **Validate wiring at wiring time, not run time** — resolve socket strings, check declared types pairwise, fail immediately naming both offending sockets | Haystack `_types_are_compatible()` / `PipelineConnectError`, `haystack/core/pipeline/base.py` [code-verified, PA2] | Goals 2, 4, 5; Candidate B. Cheapest possible guard: catches most wiring bugs before a single token is spent — and for a *self-generating* system, before a machine-authored wiring burns budget on a type error |
| P5 | **Cycles are plain edges; control flow lives in typed nodes; the backstop is global** — no loop DSL, no edge predicates. `switch`/`loop`/`iteration`/`exit_loop` are ordinary node types; termination is quiescence plus a hard per-component run cap | Haystack cycles + `max_runs_per_component` [docs-verified, PA2]; RAGFlow's control-flow-as-node-types [code-verified, PA1] | Goals 5, 10; Candidate B. **Adopt with one upgrade:** Haystack's cap is a global per-component counter, coarser than goal 10's budget object (steps, tokens, time). Take the shape, replace the counter with the injected budget |
| P6 | **Runtime-arity fan-out with reducer merge** — a routing function returns N `Send(node, payload)` objects instead of one next-node name; results merge through the receiving key's declared reducer (`Annotated[list, operator.add]`) | LangGraph `Send()` API [docs-verified, PA2] | Goal 5. Needed by any corpus-parallel or multi-hop modality; currently expressible in none of the four candidates. Steal the primitive, not the state-channel machinery |
| P7 | **A sub-graph presents as one node** — wrap an entire sub-pipeline behind a single component's `run()` signature with explicit input/output socket remapping | Haystack `@super_component` (2.12+) [docs-verified, PA2] | Goal 5's harness tier; **and Candidate D's seam** — this is the mechanism by which a sandbox part appears to the kernel as an ordinary node, making the promotion path a re-implementation behind a stable socket set rather than a migration |
| P8 | **Three artifacts, not one: trial log → promoted pinned spec → dedicated executor** — promotion is a **pure data transformation** (read the trial log, merge against the original config, emit a new clean spec with exactly one module per node); a separate `Runner` only ever sees pinned specs | AutoRAG `deploy/base.py::extract_best_config()` + `Runner` [code-verified, PA1] | Goals 7, 8. The single most directly reusable precedent for the branch→A/B→promote/rollback loop: it demonstrates promotion needs **no code change**, and that "rollback = re-pin" is trivial because promotion never mutates the original spec in place |
| P9 | **Selection is multi-metric with a hard budget pre-filter** — `filter_by_threshold()` discards trials failing a cost/speed cutoff *before* ranking survivors (with an `@avoid_empty_result` guard falling back to the unfiltered set rather than erroring to zero candidates); ranking is composite (`mean` / reciprocal-rank / `normalize_mean`), never a single raw metric | AutoRAG `legacy/autorag/strategy.py` [code-verified, PA1] | Goal 7's promote logic; PROJECT.md test dimensions 13–15 (token use is a first-class selection input, not a footnote). The empty-result guard is the kind of detail that only shows up after production contact |
| P10 | **Keep a Pareto frontier of survivors, not a single winner** — retain every candidate that is best on at least one eval instance; do not collapse to one "best" early | DSPy GEPA (arXiv:2507.19457) [docs-verified, PA2] | Goals 7, 8. Directly answers "what survives an A/B, not just who wins one race" — and is the specific defense against AutoRAG's local-optimum problem (F10) without paying for a full joint search |
| P11 | **Attribute a mutation's effect to the exact node it touched** — build an identity-keyed map from each predictor object to its structural name (`predictor2name[id(predictor)]`), walk the execution trace, and assign each extracted artifact back to the same-named node in the mutated copy | DSPy `BootstrapFewShot._prepare_predictor_mappings` [code-verified, PA2] | Goals 7 (lineage names the change) + 9 (traces name versions). Without this, an A/B tells you *a* wiring got better and nothing about *why* |
| P12 | **Two-axis identity: immutable version + an OPEN namespace of mutable aliases** — `name@<hash-or-number>` is the artifact; `name@champion`, `name@shadow`, `name@production` are reassignable pointers. Promotion **is** repointing; there is no separate promotion API. Pinning is **optional at the call site** — omitting the version means "latest", so exploratory queries pay no pinning tax | MLflow's own deprecation of stages in favor of aliases + tags (2.9) [docs-verified, PA3]; HF Hub git refs (commit/tag/branch behind one `revision` param) [docs-verified, PA3]; Feast's optional `@version` [docs-verified, PA3]; GrowthBook "promote = route 100% to the winner" [inference, PA3] | Goal 7 entirely. MLflow is the strongest evidence in the survey **because it is a walk-back**: a vendor shipped the fixed-enum design, hit its limits, and replaced it |
| P13 | **Declaration + lock split over content-addressed artifacts, with compatibility as a checkable predicate** — a human-editable intent file (the declared graph of `name@version`) and a machine-written resolution file (every hash actually used last run). Content-hash identity gives dedup and **run-level memoization** for free: skip any stage whose resolved inputs match a prior run. Recipe provenance lives in its own store, and "can component X read artifact Y" is evaluated at wiring time, never assumed | Nix `flake.nix`/`flake.lock` + store-path hashing [docs-verified, PA3]; DVC `dvc.yaml`/`dvc.lock` + `dvc repro` skip [docs-verified, PA3]; Feast version-qualified references [docs-verified, PA3]; Cognita's Metadata Store separated from the Vector DB [docs-verified, PA1] | Goals 6, 7. **This is the mechanism, not the metaphor, behind SYNTHESIS.md §5's "near-zero extra cost for query-side A/B on the same index recipe"** — two wirings that hash to the same index inputs *are* the same artifact. Also gives "reconstruct the system as run yesterday" as a read of last run's lock, not a feature to build |
| P14 | **Lineage IS the version graph; GC by reachability from named roots** — store the parent pointer on the version object itself so the commit/branch history *is* the lineage DAG; never maintain a second lineage table. Delete only what is unreachable from any named root (pinned wirings, active experiments, aliases) — never by age or count | Pachyderm (commit history = lineage), lakeFS (branch = pointer, zero-copy) [docs-verified, PA3]; Nix GC roots [docs-verified, PA3] | Goal 7. Kills failure modes F16 (side-table rot) and F18 (blind retention deleting a still-pinned version) by construction |
| P15 | **Deterministic hash assignment, sticky bucketing, and exposure logged separately from assignment** — route a query to a wiring-version by hashing a stable key (query/session id), no assignment table and no DB write; stickiness falls out of the hash; log "this unit was actually evaluated under this variant" as its own event, distinct from eligibility and from the trace | GrowthBook / Statsig [docs-verified, PA3] | Goals 4, 9. Exposure-as-separate-event is what makes "did version X get exercised enough to trust its numbers" answerable — and stops a wiring that errored before generating from silently polluting the sample |

## 3. Failure modes to avoid

**Contract & component boundaries**

- **F1 — A shared base class does not produce a shared contract.** FlashRAG declares `BaseJudger.run(item) -> bool`, but its own subclasses diverge: `SKRJudger.judge()` returns booleans, `AdaptiveJudger.judge()` returns letter labels A/B/C [code-verified, PA1]. Convention-only contracts drift between siblings. Enforce (P3), don't document. *Threatens goal 2.*
- **F2 — A shared parent does not produce shared budgets.** Every pipeline in FlashRAG's Active family hand-rolls its own loop control under a common `BasicPipeline`: `max_depth`+`beam_width` (Self-RAG), `max_iter_num`+`max_generation_length` (FLARE), `max_iter` (Self-Ask, IRCoT), `max_depth` (RQ-RAG) [code-verified, PA1]. This independently confirms SYNTHESIS.md §4 from a second codebase. *Threatens goal 10: the budget must be a machine primitive injected into every part, not a convention.*
- **F3 — Untyped node contracts push every error to run time.** LangGraph nodes are `State → Partial<State>` with no per-node declared schema, which is why it has no wiring-time-validation equivalent to `PipelineConnectError` [docs-verified, PA2]. *Threatens goal 2 — and adopting LangGraph's checkpointing must not drag this in.*
- **F4 — Stage boundaries blur under semantic strategies.** Verba's `Chunker.chunk(config, documents, embedder=None, embedder_config=None)` takes an *optional embedder* because some chunkers embed internally [code-verified, PA1]. Chunk wanting to call embed mid-stage is a real boundary violation. *Threatens Candidate A specifically — fixed-slot plain-data contracts must explicitly accommodate or forbid this, not discover it.*

**Representation & control flow**

- **F5 — DAG-only pipelines hit a wall for agentic work, and their authors know it.** LlamaIndex **removed** QueryPipeline in v0.13.0, not merely deprecated it: "the inability to perform loops in an AI application's logic is simply unacceptable" [docs-verified, PA2]. *Direct field evidence against Candidate A; direct confirmation of Candidate B's premise.*
- **F6 — Control flow leaks into edges as a graph grows branchy.** LlamaIndex's second, subtler complaint: "a lot of core orchestration logic like `if-else` statements and `while` loops get baked into the edges of the graph" [docs-verified, PA2]. The acyclic restriction was not the only problem — the *representation* became the control-flow language. *Keep conditions inside typed router/grader nodes (as CANDIDATES.md's `grade@1.0` already does), never as edge predicates.*
- **F7 — Abandoning declared-graph-as-data is the wrong retreat.** LlamaIndex's replacement (Workflows) has **no graph object at all**; topology is emergent from `@step`/`Event` type matching, and **no versioning or serialization story exists** — an explicit absence, not an unfound one [docs-verified, PA2]. Renaming an Event silently breaks every step that pattern-matched it, with no artifact to diff [inference, PA2]. *A workflow cannot be branched, mutated, or A/B'd as a spec because there is no spec. If Candidate B ever hits an expressiveness wall, the DSPy-style retreat (write Python, version the state/config it produces) comes before this one.*
- **F8 — A general declared-graph engine attracts non-RAG nodes.** RAGFlow's ~24 components include `excel_processor`, `browser`, `variable_assigner`, `string_transform` — a low-code workflow engine that RAG is one use of [code-verified, PA1]. *Candidate B should fence this deliberately rather than discover the drift.*

**Versioning**

- **F9 — Import-path-as-identity destroys reproducibility silently.** Haystack's serialized identity is a class path + kwargs; a signature change between authoring and reloading re-validates against the *currently installed* class, so a widened or renamed type can pass validation while meaning something different [code-verified for format, inference for consequence, PA2]. *The one place Candidate B must diverge hard from its closest industrial sibling.*
- **F10 — Do not mistake state versioning for component versioning.** LangGraph's channel versions are per-run execution bookkeeping (`get_next_version`, `versions_seen`), not artifact identity [docs-verified, PA2]. Candidate B needs both; conflating them yields neither.
- **F11 — Topology edits break in-flight runs, and this must be documented up front.** LangGraph states it plainly: for an interrupted thread you may add nodes/edges freely, but **renaming or removing a node the thread might resume into breaks it**, as do backward-incompatible state-key type changes [docs-verified, PA2]. This is the sharpest documented evolution hazard in the survey. *Ship the compatibility table with the checkpoint design; do not accumulate it from bug reports.*
- **F12 — Contract names are public API.** DSPy's docs state that renaming a Signature field breaks any saved state and "an optimizer that renamed them would break the program around it" [docs-verified, PA2]. Structural mapping is all-or-nothing: restructuring a Module invalidates every previously bootstrapped demo, with no partial-compatibility path [code-verified consequence, PA2]. *Goal 7's contract-version/behavior-version split must be stated and enforced, not implied.*
- **F13 — A fixed promotion enum does not survive real workflows.** MLflow shipped None/Staging/Production/Archived and **walked away from it** in 2.9: teams needed multiple simultaneous labels (`shadow` *and* `champion-eu-region`) and per-team vocabularies a closed enum cannot express [docs-verified, PA3]. *Also a warning shot at Candidate D's kernel/sandbox split if it hardens into a two-state ladder.*
- **F14 — Promotion as its own state machine reintroduces the same rigidity one layer up.** If promote becomes a bespoke workflow object (requests, gates, approvals) rather than a pointer reassignment, F13 returns at the workflow layer [inference, PA3].
- **F15 — Lineage in a side table rots.** A version gets created and its parent link doesn't; a manual hotfix bypasses the tracked path. This is the standard way lineage silently breaks [PA3, synthesized from Pachyderm/lakeFS docs]. *P14 removes the failure mode rather than mitigating it.*
- **F16 — A version pin without an environment pin is cosmetic.** ML-specific: pickle formats and CUDA/cuDNN ABI coupling mean deserialization can produce *wrong results rather than errors* [docs-verified, PA3]. Feast's generalization: versioning solves *definition* consistency but not *execution* consistency — skew reappears at the execution boundary even with the "same" version [docs-verified third-party, PA3]. *Applied here: `extractor@2.0` is incomplete without pinning the LLM/embedding model version it was tuned against, and the comparison rig must record execution-context facts (cache state, budget remaining, upstream API drift) alongside version identity, or "same version" does not imply a fair comparison. Couples goal 3 and goal 7 — red-team them together.*
- **F17 — Blind retention deletes something still pinned.** Age- or count-based cleanup (the MLOps default for artifact sprawl) cannot see a currently-pinned wiring [docs-verified, PA3]. *Use P14's reachability GC.*

**Comparison**

- **F18 — Greedy per-node search forecloses cross-stage interactions.** AutoRAG optimizes each node in isolation against the previous winner, explicitly to avoid combinatorial blow-up [docs-verified, PA1]. A bad early retrieval choice forecloses rerankers that would have paired better with a different one. *Decide explicitly; do not inherit the shortcut by default.*
- **F19 — Losing trials must stay queryable.** Once `extract_best_config` runs, AutoRAG's losing artifacts are not first-class alternatives, and there is no rig for comparing two independently-authored pipelines after the fact [code-verified, PA1]. *This is exactly the standing capability goal 4 requires and AutoRAG lacks.*
- **F20 — Zero-copy branching is a property of the storage layer, not of the word "branch".** lakeFS's cheap branching exists because objects are shared and branches are pointers [docs-verified, PA3]. *If Cozo and the vector store are not content-addressed or copy-on-write, "branch the corpus for a trial wiring" silently becomes a full copy. **Verify against Cozo's actual capabilities — do not assume by analogy.** Candidate for the spike protocol.*

**Governance / dependency**

- **F21 — Frameworks get repurposed, archived, or rewritten out from under you.** AutoRAG's `main` is now an unrelated TypeScript coding agent with the RAG optimizer demoted to `legacy/` [code-verified, PA1]. Verba: archived. Canopy: archived once Pinecone shipped a managed assistant — a business-model death, not an architectural one [inference, PA1]. fastRAG: archived January 2026, having been 100% dependent on Haystack's release cadence and forced into a compatibility rewrite by Haystack 2.0 [docs-verified, PA1]. *Never depend on an external framework by live URL or by name; vendor and pin exactly what was verified.*
- **F22 — Decorator-registration-by-import solves "findable", not "swappable".** Cognita registers via `@query_controller` plus an import in a central `__init__.py`; a component nobody imports silently does not exist, and there is nowhere to declare a version or a capability [docs-verified, PA1]. *Threatens goal 3.*

## 4. Build vs adopt

Parent project is **Nix-native** (Sourcerer v2.0) [user-stated, PA3 §1.4]; all candidate modalities are **Python** [PROJECT.md constraint]; Cozo is already in the stack; a comparison-rig precedent already exists in-repo.

**Adopt outright — already in this stack, do not rebuild**

1. **The comparison rig: generalize `tests/parity/run_substrate_parity.py`, don't write a new one.** It already does same-corpus, isolated working dir per backend, all query modes, structural diff of entity/relation sets and chunk references, JSON output [PROJECT.md context]. It generalizes from *varying storage* to *varying modality* — the axis changes, the harness doesn't. Add only what §2 says it lacks: multi-metric selection with a budget pre-filter (P9), Pareto retention (P10), and a separate exposure event (P15).
2. **The fitting contract: inherit LightRAG's `base.py` storage contracts.** Called "essentially a ready-made fitting contract" by the graph pass [SYNTHESIS.md §6]. `operate.py`'s dependency direction is already correct — storages and `llm_model_func`/`embedding_func`/`rerank_model_func` are injected [code-verified, spike 001]. Invert ownership; do not clean-sheet.
3. **The registry is three Cozo relations, not a service.** MLflow's model registry is the wrong shape (model artifacts + run tracking + a server) and its most valuable output is a *conclusion* (aliases beat stages, P12), not code. What goal 7 actually needs is: a version relation with a parent pointer, an alias relation, and a pin/root relation. Cozo is already present and is a Datalog engine — reachability GC (P14) is a recursive query, not application code.
4. **Version the graph specs in git.** Specs are text; git gives immutable commits, mutable branch pointers, tags, diff, and merge for free — and HF Hub proves the exact pattern works as a public versioning API by exposing commit/tag/branch behind one `revision` parameter [docs-verified, PA3]. Promotion = move a ref (P12). *Do not invent a parallel data model for something git already is.*

**Adopt the mechanism, with a named boundary**

5. **Nix content-addressing for component *release* identity — worth a dedicated feasibility spike, not an assumption.** A derivation hashes over source, build script, env, and every transitive dependency; the store path *is* the identity; immutability is filesystem-enforced; `flake.lock` is the resolution file; GC is reachability-based [docs-verified, PA3]. Component code + its manifest + its pinned dependency versions are exactly what a derivation hashes over — this is the one system where "adopt the pattern" and "adopt the mechanism" may be the same move [inference, PA3]. **Two honest boundaries:** (i) Nix gives *one* hash axis, while goal 7 mandates two (contract version vs behavior version) — the contract version must live in the manifest and be checked separately, not derived from the store hash; (ii) a mutation loop that proposes hundreds of prompt variants per rig run cannot afford a derivation rebuild per candidate. **Call: Nix pins released component versions and their environments (which also closes F16 — the environment pin comes free); in-flight mutation candidates use a cheap in-process content hash, and only a *surviving* candidate is promoted into a Nix-pinned version.**
6. **DSPy as a narrow dependency for prompt-shaped components.** Any component that is fundamentally a prompt — extractor, grader, rewriter, generator — gets a shipped mutation engine for free: `compile()` is the branch→score→keep operator, and GEPA's reflective evolution with Pareto retention is more sophisticated than anything we would write first [code/docs-verified, PA2]. The seam is clean: a DSPy Module is *one versioned component*; `dump_state()`'s `{instructions, demos, signature}` is exactly the mutable surface to version; a compile run is a mutation operator emitting a new `name@version` with a parent pointer. **Conditions:** pin DSPy's own version into the component pin (its version mismatches *warn rather than block* on load [docs-verified, PA2] — F16 in the concrete), and treat Signature field names as frozen contract (F12). *Do not adopt DSPy's orchestration posture — it has none.*
7. **AutoRAG: vendor two files, not the project.** `strategy.py` (the `mean`/`rank`/`normalize_mean` selection strategies, `filter_by_threshold`, the `@avoid_empty_result` guard) and the `extract_best_config` → `Runner` split are small, self-contained, and directly reusable [code-verified, PA1]. Everything around them is unusable: the repo is repurposed, the tree is `legacy/`, the search is greedy (F18), the losers are discarded (F19), and the node lines are linear. **Vendor from tag `legacy-v0.3.24`, pinned; never depend on the live repo (F21).**

**Build — the seam nobody has shipped**

8. **The executor: build a Haystack-*shaped* engine; do not take the Haystack dependency.** Copy the protocol (typed sockets, wiring-time validation P4, cycles-as-edges P5, `warm_up()`, SuperComponent nesting P7) — the design is right and PA2 verified it against source. Take the dependency and you inherit exactly the thing goal 7 forbids (import-path identity, F9) plus fastRAG's fate (F21: 100% upstream ABI dependence, killed by the 2.0 rewrite). *The middle option, named honestly: run Haystack as the executor with a `name@version` → import-path resolver rewriting specs before load. It buys the executor cheaply and costs a translation layer that must be correct on every socket, plus permanent exposure to Haystack's release cadence. Given that node identity is the project's one novel contribution, putting a translation shim at that exact seam is the worst place to economize — but the option should be scored by the red team rather than dismissed here.*
9. **Node identity with lineage inside a declared graph — genuinely novel relative to this survey.** Not prior art anywhere in 18 systems [PA2 §5, PA1 cross-cutting]. This is the one thing to build carefully. Everything else in §2 is portable.
10. **Do not adopt: lakeFS/Pachyderm, Feast, DVC, GrowthBook/Statsig, MLflow, FlashRAG/RAGFlow/Cognita/Verba/Canopy.** Patterns only. Specifically: lakeFS solves object-storage branching we do not have (our corpus is Cozo + vector namespaces — P13's content addressing gives cheap branching directly, *if* F20 checks out); DVC's declaration/lock split is already supplied by Nix in this stack and a second lock system is pure cost; GrowthBook's three useful mechanisms (hash assignment, sticky bucketing, exposure event) are a few lines each, not a platform; FlashRAG's value is as a **port source** — 23 published methods with readable source and a taxonomy that maps almost 1:1 onto ours [docs/code-verified, PA1] — not as a dependency.
